## 三、新增设计修正（C10 ~ C14）

### C10 · `stocks` 在**发布回执中恒为 null**，层级校验时机必须后移 ⚠️ 高优先级

**现象**：`POST /api/manage/wfStartPublish` 返回的 `data` 里 `stocks = None`；而报告完成后的 `GET /api/home/getDetail` 与 `GET /api/home/getList` 记录中，`stocks = "宁德时代,300750,积极,A"`。

**根因**：`stocks` 是**报告生成结果字段**，报告未完成时为空。

**影响**：原 SOP 第 ④ 步写的「**发布回执校验**：读返回记录的 `stocks` 挂载数」**执行不了**——回执里根本没有该值。

**修正**：层级校验的时机从「发布完成时」**后移到「报告完成后（getDetail / getList）」**。

> **代价评估**：后移意味着层级错配**只能在生成完成后发现**（浪费一次生成），无法完全避免首轮实验 P3 组的浪费。**降级方案**：发布前用「模板全量表」的**静态层级映射**做前置拦截（个股任务禁止选 3002 —— 这条仍有效，因为是靠 tid 静态判断，不依赖 stocks）。**即：静态层级拦截（发布前，有效）+ 动态层级复核（完成后，兜底）。**

### C11 · 轮询调用异常 ≠ 报告失败 ⚠️ 高优先级

**现象**：本次脚本轮询第 3 轮起连续 15 轮返回 `err`，但复查发现**报告实际已于 52 秒完成（status=public）**，`err` 来自脚本把**调用异常**（`except` 分支）与**报告 error 状态**混为同一个变量。

**根因**：服务端在短时间内被高频轮询时会出现**瞬时异常/限流**（脚本静默 catch 后统记为 `err`）。事后连续 6 次探测 **6/6 正常**。

**影响**：若按"err 即失败"处理，会**误判报告失败**，并因非终态而继续空转轮询（本次空转至 20 分钟上限）。

**修正**：轮询必须**区分两类失败**——
```
status = data.status            # 报告状态：inprogress / public / private / error
调用异常（超时/非 JSON/5xx） → 不计入 status，走「重试 + 指数退避 + 站点回退」
连续 N 次（如 5 次）调用异常  → 切换站点重试；仍失败才上报「无法获取状态」
只有 data.status == "error"   → 才是报告失败
```

### C12 · 生成耗时区间进一步扩大：**约 1 分钟 ~ 13+ 分钟**

**现象**：本次 **52 秒**完成；此前实测轻体量 2.5~5 分钟、tid=1001 首测 >13 分钟。

**修正**：耗时口径改为「**通常 1~5 分钟，个别情况可达 10 分钟以上**」，且**抖动来自服务端**。轮询上限维持 40 次（20 分钟）不变；**但对短耗时模板（如 tid=9）应在前 2 分钟内以更短间隔（如 10 秒）探测**，避免白等 30 秒一轮。

### C13 · 校验必须**优先校验估值链的"输入锚点"**，而非只校验结论

**现象**：深挖的估值链是 `PE 18x / PB 3.2x / 股息率 1.2%` → 估值弹性表 → `DCF ￥345` → 目标价区间 → "折价 15%、安全边际充足"。**三个输入锚点全部失真**（实际 PE 15.98x / PB 3.64x / 股息率 2.80%），于是整条链作废。

**修正**：校验顺序调整为——
```
先校验「估值链输入锚点」（当前 PE / PB / 股息率 / ROE / 增长率）
  ├─ 任一锚点偏差 > 5% → 该锚点之后的全部估值推演「整体作废」，不逐项校验
  └─ 锚点全部一致 → 再逐项校验估值结论
```
> 原设计只规定"估值类数字不得引用"，但没规定**发现锚点失真后应整链作废**。若不整链作废，会陷入"逐项校验 6 个目标价与 4 个弹性系数"的无谓劳动。

### C14 · 内部自相矛盾**并非个别模板的问题**

**现象**：本次 tid=9（价值型模板）同样出现内部矛盾——「风险情景…目标价 -30%」vs「悲观 ￥282.9（-3.6%）」。

**修正**：把"内部一致性检查"从"特定模板注意项"提升为**每份深挖报告的固定检查项**（列入校验表 D 类）。

## 五、校验后新增的「诚实性」行为

本轮出现一个设计预期外的正向行为：**在数据源未取 D7（行业/产业链）的情况下，成稿拒绝输出目标价**，只给"触发条件 + 观察指标"。

这说明「无来源不结论」（红线 2）**在估值环节自动生效**——深挖的估值数字被作废后，模式**不会**退而求其次去采纳深挖目标价，而是**如实声明"不足以支撑独立估值推导"**。

> 这正是 50/50 设计的初衷：**当深挖的数字不可用时，数据源仍能撑住事实层，而估值结论可以诚实地缺失，而不是伪造一个。**
