## 发布计划（v1.12.0 新增）

> **规则**：**报告份数由模板能力、具体问题、有效复用共同决定** —— **不得默认「一家公司等于一份报告」**，
> **不得为凑齐计划而给「直取 / 计算 / 已有资料足够」的问题新增报告**，**也不得静默缩减**用户要求的对象数量。
> 一份报告可支持多个问题，一个问题也可需要多份报告；对应关系必须明确写清。
> 生成与执行入口：`skills/shenwa-hybrid/scripts/publish_plan.py`（`build()` / `gate()` / `publish()`）。

| 条目编号 | 对象 | 对应问题 | 模板 tid | 本次用途 | 为什么需要新报告（缺什么） | 输入材料 | 模板成本 | 预计消耗 | 历史报告检查 | aid | 状态 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| `<YYYYMMDD-NN>` | `<代码 名称>` | `<Q1, Q2>` | `<tid>` | `<一句话>` | `<实质证据缺口>` | `<引用>` | `<cost 或 unknown>` | `<Σ 或 unknown>` | `<no_candidate / candidate_unverified / unknown>` | `<发布后回填，整串含 @@>` | `<pending / pending_authorization / accepted / done / failed / submit_unknown>` |

- **条目编号在提交前生成**，**不按服务端返回顺序分配**；aid 回来时**绑定原条目**，再关联对象与问题；
  并发下即使 aid 乱序返回，也**不会串对象、串问题**。
- **预计成本 = Σ(各条目模板成本)**，来源 = `templates` 接口 `data[].templates[].cost`；
  **成本取不到 → 标 `unknown`，不按 0 处理**；模板价格只用于**估算**，**只有获得扣点依据才标「实际消耗」**。
- **预算三分**：**已结算消耗** / **尚未结算的预留占用** / **拟新增** —— 已结算**不再计入预留**；
  **账户余额 ≠ 用户允许本次全部花费的额度**；数量提醒阈值**不自动缩减研究范围**，也不替代预算检查。
  用户已授权的范围与消耗内**不再逐份询问**；超出授权时**只暂停受影响的条目**并保留待执行事项。
- ⚠️ **aid 只代表服务端受理**，**不等于报告完成、更不等于用户问题已回答**；
  提交结果未知（`submit_unknown`）时**保留占用、不换站重发**，
  只有确认未产生消耗或取得明确结算依据后，才调整占用。

## 背景与来源（v1.13.0 新增）

> **规则**：发送给深挖的背景**一律经 `publish_plan.assemble_background()` 组装**，
> 并**记录实际发送的文字**（`publish()` 回填 `sent_params` / `sent_text`）。
> **不假设深挖能读本地路径 / 文件名 / 内部材料编号** —— 实际发送的文字必须**能独立理解**。

| 背景条目 | 传送要求 |
|---|---|
| 经核实且影响本次分析的数字 | **可以传入**，但**保留来源 / 时间 / 单位 / 口径** |
| 未核实材料 | 可以传入，**必须标明状态**（「尚未独立核实」） |
| 用户观点 | 表述为**待检验命题**，**不得改写成已确认事实** |
| 既有判断（解释 / 验证时） | 可以提供，**注明来源 / 时间 / 用途** |
| 预设结论（独立判断当前状态时） | **一律不注入**（`independent` 模式） |

- **只选择本次研究需要的关键背景**，完整材料保留在本地记录中。
- 压缩背景**不得改变**数字 / 单位 / 时间 / 条件 / 核实状态，**不得机械截断**。
- 🔴 **超出 `text` 长度上限（500 字）→ 必须先调整问题条目或执行方式**，
  并**重新检查需求覆盖与预算**；**不得静默删除关键约束后继续发布**。

### 来源关系与复用（v1.13.0）

- 材料登记至少追踪：**对应对象与问题编号 / 材料编号 / 来源名称与可核对位置 /
  材料所属时间·公开时间·获取时间（未知显式标记）/ 指标含义·单位·统计口径 / 核实状态 /
  属于原始事实·计算结果·外部判断·用户待检验观点 / 与其他材料的引用·转述·底层同源关系**。
- **深挖复述已传入的背景数字，不算新增独立证据**；**不同接口指向同一底层材料不自动算独立验证**；
  来源关系无法确认时**标 `unknown`**（**不默认独立、不武断同源**）；
  **不得仅因两个结果一致就写「两路独立验证一致」**。
- 历史报告**按内容判定**能否复用：列表 / 标题 / 模板 / 对象 / 日期**只用于找候选**；
  四档为**完整复用 / 部分复用 / 仅历史参考 / 不适用或待核实**。
  **同日同对象同模板但问题不同不得直接复用**；表述不同而问题相同且条件有效**可以复用**；
  跨日**稳定信息可用、时效数据须重查**，旧结论依赖已变数据**必须重新分析**。
- 实现：`skills/shenwa-hybrid/scripts/reuse.py`（内容判定）+ `publish_plan.py`（背景组装）。
### 监测与跨期比较（v1.14.0）

- **进入监测的四种情形**：用户要求**持续跟踪**某对象/问题；要求与**上次 / 指定日期 / 指定阶段**比较；
  要求**检验、更新此前判断**；本次任务**属于已建立的监测序列**。
  普通一次性查询**沿用现有交付方式，不强行增加无关趋势分析**。
- **监测记录**（落成可追溯记录，**优先复用前四轮的问题 / 材料 / 证据 / 报告记录，不复制不一致数据**）：
  以**稳定监测序列编号**把历次任务及问题编号关联到同一研究目标（**不凭对象简称 / 文件名 / 本次任务编号匹配**）。
  每条至少含：记录编号 / 序列编号 / 任务与问题编号 / 稳定对象标识·名称·研究范围 /
  研究截止时间·记录生成时间·材料时间 / 关键指标·数值·单位·统计期间·计算口径 /
  证据引用·来源关系·核实状态·数据版本 / 当次判断·依据·假设·未确认事项 / 分析规则版本 /
  数据缺口·样本范围 / **原始·修订·事后重建**三分及对应关系。**只记录实际获得的数据与判断，不为补齐字段编造内容**。
  **原始快照保存后不覆盖**；数据修订 / 规则调整 / 判断修正**形成新记录并关联旧记录**；
  **同一任务重复归档不制造新观测**，同一数据时点多个修订/重算版本**不计为多个连续时间点**。
- **基线选择**：**指定优先**（用户指定比较日期/记录时采用）；未指定时取**当前研究时点之前同序列最近的适用记录**并说明实际比较日期。
  **不按文件修改时间 / 下载顺序 / 报告返回顺序选**。区分**确无历史 / 有条件不可比 / 读取失败或信息不足**三态：
  **读取失败 ≠ 无历史**，不得覆盖已有记录；历史重建须说明依据，并区分「当时可知」与「事后重算」。
- **可比性先行**：比较前核对对象 / 问题 / 指标定义 / 单位 / 统计期间 / 样本范围 / 分析规则；
  可统一口径则**重算另存**、不可统一则**标不可比及原因**、部分不可比**不妨碍其余继续**。
  **缺失值不补 0**；**基数 0 不硬算变化率**；类别/阶段按**状态迁移**比较；
  变化**区分数值差 / 百分比 / 百分点**。
- **变化与归因**：回答四问——**哪些变了 / 哪些有延续性 / 新证据支持·削弱·推翻原判断还是不足 / 变化来自对象本身·数据修订·口径·规则还是多因**。
  **允许「原因暂无法判定」**，不强行归因；**数值上升 ≠ 改善、下降 ≠ 恶化**；**只有两个时点不得称持续趋势**；
  **事实变化与判断变化分开**，**规则变化或历史数据修订不写成研究对象变化**。
- **成稿前完成比较**：比较在**成稿前**完成，不在交付后只存一个无人使用的比较文件；
  最终回答呈现**本次结论 / 相比基线的主要变化 / 对原判断的支持或修正 / 待跟踪事项**；
  **没有变化可明确说明、没有依据不填充推演**。需要新报告时继续经路由 / 内容复用 / 参数校验 / 发布检查 / 预算，
  **不因新增监测就默认重生成报告**。
- 实现：`skills/shenwa-hybrid/scripts/monitor.py`（`run_monitor_flow()` / 监测序列编号 / 基线选择 / 可比性 / 变化计算 / 归因 / 四问）。
  未接入真实调度时不宣称具备自动定时运行或主动推送。
