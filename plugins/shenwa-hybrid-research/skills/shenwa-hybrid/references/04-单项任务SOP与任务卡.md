# 04 · 单项任务 SOP 与任务卡

## 一、七步闭环 SOP

### ① 任务受理
- **输入**：客户一句话需求
- **动作**：补齐四个要素——标的、时间范围、交付物、交付格式；缺失则一次性问清，不问第二次
- **输出**：任务卡草稿
- **验收**：能用一句话复述"这次要交付什么"

### ② 偏好注入
- **输入**：`profile.yaml`
- **动作**：读取偏好并**分成两组**（v1.9.0）——**表达偏好**（语言 / 长度 / 图表 / 结构 / 关注重点）与**任务约束**（研究期限 / 比较目标 / 风险限制 / 明确指定的方法），生成本次生效参数集；若本次客户有临时指令（如"这次结论写保守一点"），以临时指令覆盖，但**不改写偏好文件**
- **输出**：生效参数集
- **验收**：能说明本次的估值方法、时间视角、结论口径；并确认**偏好只改表达与范围，未改写事实**

### ③ 路由判定
- **输入**：任务卡草稿 + 生效参数集
- **动作**：走 `02-能力分工与路由.md` 的决策树。**六步顺序不可颠倒（v1.7.0）**：
  1. **研究问题**（事实 / 机制 / 比对 / 筛选 / 状态）
  2. **对象与范围**——含 Q0 标的层级（红线）；**对象数量只产出「批量方式」**，不决定分析类型
  3. **指标族**——**唯一决定「用哪个能力」的一步**；`get_right_side` 只用于「右侧状态」，乖离率 / 估值 / 财务比较各走适配能力
  4. **时间范围**（绝对 / 相对 / 前瞻 / 当前截面）
  5. **所需深度**（fact / state / list / comparison / deep_research）
  6. **可用能力**——按权限与状态过滤；`unverified` / `unavailable` **不得承诺**
  7. **多维需求登记**（v1.11.0）——把用户一次提出的**每个问题**单独登记（编号 / 原话 / 对象 / 时间 / 事实·计算·解释 / 指标族 / 证据 / 执行方式 / 状态 / 回答位置）；⚠️ **问题数量 ≠ 指标族数量**，**不得按指标族合并问题**
  再 **Q0.8 初判执行方式**（直取 / 计算 / 现有资料 / 报告候选 / 如实列缺——**「分析」二字与族数都不决定是否发报告**）→ Q0.9 判数据形态（**判据 = 指标族 + 深度**）→ 定任务类型与分工比例 → **Q5 校验模板层级**（重体量模板不得与 `light` 组合；**2001 仅个股层级可用**）
- **输出**：任务卡（含标的层级、分工声明、模板体量等级）
- **验收**：分工比例有依据，偏离基准已写明理由；标的层级与所选模板的层级一致

### ④ 并行取数
- **输入**：任务卡
- **动作**：
  - 深挖侧（**v1.12.0 改版：逐份发布一律经真实发布入口**）：
    `user_info` 检查余额与有效期 → `templates` 匹配模板（**取各模板 `cost` 作为成本依据**）
    → `publish_plan.build(问题清单, …)` **生成发布计划**（含 `entry_id`，**提交前生成**）
    → `publish_plan.publish(item, client=…)` **逐份发布**（`gate()` 通过才真的调 `report_publish`）
    → 取 aid **回填原条目**（**不按返回顺序分配报告**）
    - 🔴 **不得在 SOP 里直接调 `report_publish`** —— 那样会绕开必要性 / 历史报告检查 / 计划覆盖 /
      授权预算 / 参数一致性五项检查。**旧调用路径一律改经 `publish_plan.publish()`**
    - **发布会话顺序（v1.12.0）**：① 问题清单 → ② 发布计划（`entry_id` 先定）→
      ③ 最终检查（取得模板成本后、提交前）→ ④ 预算预留
      （**「检查剩余额度 + 预留本次成本」是不可被并发插入的一个操作**）→
      ⑤ 提交并绑定 aid → ⑥ 状态回填（`accepted` **≠** `done`）
    - ⚠️ **aid 只代表服务端受理**：不等于报告完成，**更不等于用户问题已回答**
    - ⚠️ **成本未知不按 0**：模板 `cost` 取不到 → 标 `unknown` → `confirm_required`，不发；
      **账户余额 ≠ 授权额度**；数量提醒**不自动缩减研究范围**
    - **（v1.13.0）轮 0 · 背景与来源前置**：先做**来源登记及核对**（材料 9 类追踪项，**未知显式标记**）→ **历史报告内容检查**（`reuse.judge_all()` **逐题**四档：完整复用 / 部分复用 / 仅历史参考 / 不适用或待核实）→ **确定复用部分与研究缺口**（**完整复用的内容进入该问题的证据与回答，不只是取消发布**；部分复用**保留未解决的问题**、条目收窄后仍发布）
    - **（v1.13.0）背景组装**：对必要的新报告用 `publish_plan.assemble_background()` 组装 `text` —— **已核实数字带来源 / 时间 / 单位 / 口径**、**未核实材料标状态**、**用户观点写成待检验命题**、**独立判断时**不注入既有判断 / 预设结论、**解释 / 验证既有判断**时可提供并注明来源 / 时间 / 用途；
      🔴 **不假设深挖能读本地路径 / 文件名 / 材料编号**（发送文字必须能独立理解）；**超限不静默截断** → 调整条目 / 执行方式并**重新检查覆盖与预算**
    - **（v1.13.0）调整后重检**：复用或背景导致计划调整 → `publish_plan.recheck_after_reuse()` **按剩余问题重新生成参数并重算 `plan_hash`**、`reuse.recompute_plan_cost()` **重算预计新增消耗**并核对已有授权；**已提交 / 结果未知条目的状态与预算占用一律保留**
    - **`text`（背景消息）为必填**，即使内容很短也要给；完全缺省会返回 `status=SRV` 参数缺失
    - **背景消息中的日期必须与系统当日一致**，否则会被深挖的**时间截面语义校验**拒绝
  - **发布前静态层级拦截（C10 修正）**：按 Q5 的「模板-层级静态映射」在**发布前**拦截
    - ⚠️ **不要读发布回执的 `stocks`** —— 实测该字段在 `wfStartPublish` 回执中**恒为 null**（它是**报告生成结果**字段，只有完成后才在 `getDetail`/`getList` 中填充）
    - 个股任务 → 禁止 tid=3002（板块级 + 重体量）、禁止 tid=12（市场/事件级）
    - 板块 / 产业链任务 → 必须选对应层级的模板
    - 命中即重选模板，**不消耗生成**
  - ⚠️ **指标族 = 右侧状态（且深度为「名单 / 分布」）→ 本步不发报告**：改走 `get_right_side` 直取（0 点、秒级），并跳过 ⑤ 的轮询与层级复核（详见「二·补 · 右侧状态族横截面 SOP」）。**对象数量只决定批量方式**，**不构成**走该通道的理由
  - 数据源侧：并行拉取 D1~D9 所需数据
  - **注意**：若偏好为「均衡」或「交易面主导」，数据清单中**必须**勾选 D3 资金流向与 **D9 技术指标**（v1.7.0 编号修正：技术指标是 **D9**，原误写为 D4），否则权重设置不生效
- **输出**：深挖 aid + 数据包
- **约束**：**必须告知客户"一般 1~5 分钟，个别模板可能超过 10 分钟"**，不得假装实时完成

> **耗时抖动提示（两次实跑新增）**：深挖同一量级模板的生成耗时可能相差 **10 倍以上**（实测 tid=9 为 **52 秒**、tid=1001 首测 >13 分钟而复测 2.5 分钟）。慢生成不等于失败，**不要提前判定超时**。

### ⑤ 交叉校验
- **输入**：深挖报告全文 + 数据包
- **动作**：
  - **轮 0 · 数据口径前置（v1.4.0 新增，先于一切比对）**：按最小字段约定（对象标识 / 指标定义 / 数值 / 单位 / 所属期间 / 公开或生效时间 / 取数时间 / 来源 / 处理方法）登记每条数据，**缺失记「未知」，不补造**；区分 半年度 / 全年 / 单季 / TTM、MA 与 EMA、绝对与相对表现、指标水平与变化量、百分比与百分点；**先检查可比性，再计算差异**——相对偏差的分母统一取**基准值**，基准为 0 / 接近 0 / 符号变化 / 口径不可比时**明确处理，不机械套比例阈值**。执行入口：`python3 skills/shenwa-hybrid/scripts/data_qc.py`（`records` / `checks` / `selftest`）。**数据冲突时保留原值与来源、标冲突，不擅自选一个数充当真值。**
  - **轮 1**：数据源内部一致性校验（先做，通过的数据才可作为轮 2 基准）
  - **轮询（C11/C12 修正）**：`report_status` 轮询至 public/private/error
    - **探测间隔**：前 2 分钟每 **10 秒**（短耗时模板最快 52 秒即可完成），2 分钟后每 **30 秒**；上限 **40 次 / 20 分钟**
    - **必须区分两类失败**：只有 `data.status == "error"` 才是报告失败；**调用异常**（超时/非 JSON/5xx）不计入状态，走重试+退避，连续 5 次异常则切换站点，仍失败只上报「无法获取状态」，**不得报「报告失败」**
    - （实测教训：脚本曾连续 15 轮异常，而报告实际已 52 秒完成 → 误判失败并空转 20 分钟）
  - **动态层级复核（完成后，兜底）**：读 `report_detail` 的 `stocks` 挂载数——任务为「个股」而挂载数 > 2、或「板块/产业链」而 < 3，则告警层级错配
  - `report_detail` 读取全文
  - **若任务含估值结论，先验「估值链输入锚点」（C13+C16）**：逐项核对 PE / PB / 股息率 / ROE / 增长率 / FCFF 基期；锚点失真只作废**真正依赖该锚点**的推演（不再「整链作废」）；与该锚点无关的推演照常保留，**不因某个无关指标偏差而废弃整份报告**。⚠️ **不得因结论数字恰好落在合理区间而跳过锚点校验（C16）** —— 结论"碰巧接近"不等于推导正确
  - 抽取正文中全部可验证数字，**轮 2**：逐项与数据源比对，**按分层采信规则判定**（已披露财报科目可用；推算类比率、估值类数字、阈值价格类不得引用）
  - **逐项检查是否存在拦截级项**（偏差 > 50% / 量级错误 / 方向性误判）→ 发现即作废，不得并列保留
  - **估值门（v1.6.0 修正）**：先做**现金流与折现率配对**（FCFF↔WACC → 企业价值，须经「＋现金及非经营资产 －有息债务 －少数股东权益 －优先股」桥接得股权价值；FCFE↔股权资本成本 Ke → 股权价值，不再减债务）；再**逐方法检查必要输入与适用条件**——**某方法输入不足时只停止该方法**，齐备的方法**一个也算数**（取消「至少两种方法」，也取消「缺 D7 即拒绝输出」）。方法齐备时并列呈现并**解释差异**；⚠️ **接近程度 ≠ 准确度**，**不得**因结果偏低或偏离而剔除，也不得静默取平均；永续增长率 ≥ 折现率时**阻止该公式**并改用其他口径。实现：`skills/shenwa-hybrid/scripts/valuation.py`
- **输出**：校验表（含拦截级标记、输入锚点分区、方法收敛矩阵）
- **约束**：校验覆盖率须达 100%；深挖声称的数据缺口须用数据源实测核对；估值**只给区间与触发条件，不给单点目标价**

### ⑥ 成稿交付
- **输入**：全部材料
- **动作**：**先定交付形态**（短答 / 比较表 / 简析 / 完整报告，由任务深度与问题类型决定，**不按篇幅**），再按 `05-输出规范与校验表.md` 组装——**只有「完整报告」用六段结构**，其余形态按需要呈现，但**关键问题的回答必须完整、重要结论必须有依据、证据不足必须可见**
- **输出**：最终交付物（markdown / table / pdf / xlsx）
- **约束（v1.9.0）**：**格式转换不得改变**结论、数字与验证状态；深挖官方原文 PDF 标为「**原始报告**」，专家包综合版 PDF 当前环境不支持生成时**须说明并改交 markdown / table / xlsx**
- **约束**：
  - 深挖分析主体照录（来自**归档件**），不摘要；**归档件完整保留全文**，含已确认错误的段落
  - **估值段须标注输入类别**：历史观测 / 已披露事实 / 未来假设 / 估计值 / 计算结果分开标注；历史 CAGR 外推一律标为**预测假设**（附预测期限、适用理由、敏感性），**不得**称为"已验证的未来增长率"
  - **但全部数字以数据源为准**——深挖原文中的数字一律不得直接进入结论段与风险段
  - **已确认错误的原文不得继续支持正文结论**；如需展示须标为「错误对照」且不进摘要
  - 事件类信息须已由数据源独立确认
  - ★ **先过「证据采信门」（轮 3，v1.5.0）**：结论↔证据绑定 → 按证据状态**保留 / 降级 / 改写 / 撤回 / 移入历史背景**；未独立核实的不进「已确认事实」；资料不足则**收缩交付范围**并说明缺项与影响
 

### ⑦ 归档修正
- **输入**：本次任务全过程
- **动作**：记录偏差、客户反馈；识别重复出现的反馈模式；给出偏好演进建议
- **输出**：任务归档 + 修正日志条目
- **触发规则**：同一类反馈连续出现 3 次 → 主动建议修改偏好，并说明理由


## 二、任务卡标准结构

任务卡是单项任务的唯一凭证。**一个任务卡 = 一个交付单元**：可以是一个简单问题，也可以是**一个总任务包含多个共享数据的子任务**（如「扫描 + 比较 + 解释」），但**必须形成统一结论**、**不得**把与主题无关的事项打包进来。

- 日期：<YYYY-MM-DD>
- 客户：<姓名>
- 状态：草稿 / 执行中 / 待校验 / 已交付 / 已归档

  > 判定见 `02-能力分工与路由.md` 的 **Q0.9（v1.7.0 判据改版）**：**只有「指标族 = 右侧状态」**（右侧 / 阶段 / 迁移 / 否决 / 资格）**且深度为「名单 / 分布」**时，才走「结构化直取」通道（S11），**不发任何报告**。

## 发布计划（v1.12.0 新增）

> **规则**：**报告份数由模板能力、具体问题、有效复用共同决定** —— **不得默认「一家公司等于一份报告」**，
> **不得为凑齐计划而给「直取 / 计算 / 已有资料足够」的问题新增报告**，**也不得静默缩减**用户要求的对象数量。
> 一份报告可支持多个问题，一个问题也可需要多份报告；对应关系必须明确写清。
> 生成与执行入口：`skills/shenwa-hybrid/scripts/publish_plan.py`（`build()` / `gate()` / `publish()`）。

| 条目编号 | 对象 | 对应问题 | 模板 tid | 本次用途 | 为什么需要新报告（缺什么） | 输入材料 | 模板成本 | 预计消耗 | 历史报告检查 | aid | 状态 |
|---|---|---|---|---|---|---|---|---|---|---|---|

- **预计成本 = Σ(各条目模板成本)**，来源 = `templates` 接口 `data[].templates[].cost`；
  **成本取不到 → 标 `unknown`，不按 0 处理**；模板价格只用于**估算**，**只有获得扣点依据才标「实际消耗」**。

## 三、粒度控制准则

| 粒度过大（禁止） | 粒度过小（无意义） | 合适粒度 |
|---|---|---|
| "帮我分析整个新能源产业链" | "查一下宁德时代今天收盘价" | "分析宁德时代在动力电池环节的竞争位次" |

**判定标准**：如果任务的产出无法用"一份可交付物 + 一张校验表"承载，说明粒度过大，需要拆分——但**同一主题、共享数据的多个子任务应合并为一个总任务**（统一结论），而不是拆成多张卡重复取数（v1.9.0）。


## 四、并行任务处理

客户一次提多个**互不相关**的任务时，**拆成多张任务卡**，而不是合并成一张。执行时可并行取数、串行交付。

> ⚠️ **两类不要混淆（v1.9.0）**：
> ① **复合任务**（同一主题下的多个子任务，如「扫描 + 比较 + 解释」）→ **放在同一个总任务里**，子任务**共享经过验证的数据**、按键去重、同一键不同值时**并列原值并标冲突**，最终给出**统一结论**——避免重复取数与零散交付。
> ② **仅查询 / 仅整理用户提供的材料** → **只做被要求的事**，**不得**自动扩展成新的深度研究（不额外发报告、不追加未要求的分析）。

```
客户："帮我看看宁德时代，顺便把昨天市场也复盘一下"
  ↓
任务卡 20260925-01 · 宁德时代竞争位次分析（研究型，50/50）
任务卡 20260925-02 · 9月24日市场复盘（数据型，深挖 30%）
  ↓
并行取数 → 各自校验 → 分别交付
```


## 五、异常处理

| 异常 | 处理 |
|---|---|
| 深挖报告状态 error | 重试一次；仍失败则交付数据层成果，并说明深挖侧未完成 |
| 深挖轮询超时（>20 分钟 / 40 次上限） | 告知客户仍在生成，先交付数据层，稍后补交主体部分。⚠️ 慢生成 ≠ 失败，抖动可达 30 倍以上（实测 25 秒 ~ 13+ 分钟） |
| 深挖点不足 | 发布前 `user_info` 拦截，提示充值（微信 shenwa4119），不静默失败 |
