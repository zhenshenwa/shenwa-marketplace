# 04 · 单项任务 SOP 与任务卡

## 一、七步闭环 SOP

### ① 任务受理
- **输入**：客户一句话需求
- **动作**：补齐四个要素——标的、时间范围、交付物、交付格式；缺失则一次性问清，不问第二次
- **输出**：任务卡草稿
- **验收**：能用一句话复述"这次要交付什么"

### ② 偏好注入
- **输入**：`profile.yaml`
- **动作**：读取 `identity` / `data_weights` / `output`，生成本次生效参数集；若本次客户有临时指令（如"这次结论写保守一点"），以临时指令覆盖，但**不改写偏好文件**
- **输出**：生效参数集
- **验收**：能说明本次的估值方法、时间视角、结论口径

### ③ 路由判定
- **输入**：任务卡草稿 + 生效参数集
- **动作**：走 `02-能力分工与路由.md` 的决策树。**顺序不可颠倒**：
  1. **Q0 先定标的层级**（个股 / 板块 / 行业 / 产业链 / 宏观）——层级优先级最高，个股任务不得指派板块级模板
  2. 再定任务类型，确定分工比例
  3. **Q5 校验模板体量**——重体量模板不得与 `light` 配比组合
- **输出**：任务卡（含标的层级、分工声明、模板体量等级）
- **验收**：分工比例有依据，偏离基准已写明理由；标的层级与所选模板的层级一致

### ④ 并行取数
- **输入**：任务卡
- **动作**：
  - 深挖侧：`user_info` 检查余额与有效期 → `templates` 匹配模板 → `report_publish` 异步提交 → 取 aid
    - **`text`（背景消息）为必填**，即使内容很短也要给；完全缺省会返回 `status=SRV` 参数缺失
    - **背景消息中的日期必须与系统当日一致**，否则会被深挖的**时间截面语义校验**拒绝
  - **发布回执校验**：读取返回记录的 `stocks` 字段，数一下挂载了几个标的
    - 任务为「个股」而挂载数 > 2 → 层级错配，立即重选模板（**不要等产出再发现**）
    - 任务为「板块/产业链」而挂载数 < 3 → 同上
  - 数据源侧：并行拉取 D1~D8 所需数据
  - **注意**：若偏好为「均衡」或「交易面主导」，数据清单中**必须**勾选 D3 资金流向与 D4 技术指标，否则权重设置不生效
- **输出**：深挖 aid + 数据包
- **约束**：**必须告知客户"一般 1~5 分钟，个别模板可能超过 10 分钟"**，不得假装实时完成

> **耗时抖动提示（两次实跑新增）**：深挖同一量级模板的生成耗时可能相差 **10 倍以上**（实测 tid=9 为 **52 秒**、tid=1001 首测 >13 分钟而复测 2.5 分钟）。慢生成不等于失败，**不要提前判定超时**。

### ⑤ 交叉校验
- **输入**：深挖报告全文 + 数据包
- **动作**：
  - **轮 1**：数据源内部一致性校验（先做，通过的数据才可作为轮 2 基准）
  - **轮询（C11/C12 修正）**：`report_status` 轮询至 public/private/error
    - **探测间隔**：前 2 分钟每 **10 秒**（短耗时模板最快 52 秒即可完成），2 分钟后每 **30 秒**；上限 **40 次 / 20 分钟**
    - **必须区分两类失败**：只有 `data.status == "error"` 才是报告失败；**调用异常**（超时/非 JSON/5xx）不计入状态，走重试+退避，连续 5 次异常则切换站点，仍失败只上报「无法获取状态」，**不得报「报告失败」**
    - （实测教训：脚本曾连续 15 轮异常，而报告实际已 52 秒完成 → 误判失败并空转 20 分钟）
  - **动态层级复核（完成后，兜底）**：读 `report_detail` 的 `stocks` 挂载数——任务为「个股」而挂载数 > 2、或「板块/产业链」而 < 3，则告警层级错配
  - `report_detail` 读取全文
  - **若任务含估值结论，先验「估值链输入锚点」（C13+C16）**：逐项核对 PE / PB / 股息率 / ROE / 增长率 / FCFF 基期；**任一锚点偏差 > 5% → 该锚点之后的全部估值推演整链作废**，不再逐项校验下游目标价。⚠️ **不得因结论数字恰好落在合理区间而跳过锚点校验（C16）** —— 结论"碰巧接近"不等于推导正确
  - 抽取正文中全部可验证数字，**轮 2**：逐项与数据源比对，**按分层采信规则判定**（已披露财报科目可用；推算类比率、估值类数字、阈值价格类不得引用）
  - **逐项检查是否存在拦截级项**（偏差 > 50% / 量级错误 / 方向性误判）→ 发现即作废，不得并列保留
  - **估值段须多方法交叉验证（C17）**：至少两种方法（股息率法 / PB-ROE / 相对 PE / DCF），报告**收敛度**；中性值差异 > 15% 的离群方法**必须说明原因**（如 DCF 的 WACC 高于实际 ROIC），不得静默取平均
- **输出**：校验表（含拦截级标记、输入锚点分区、方法收敛矩阵）
- **约束**：校验覆盖率须达 100%；深挖声称的数据缺口须用数据源实测核对；估值**只给区间与触发条件，不给单点目标价**

### ⑥ 成稿交付
- **输入**：全部材料
- **动作**：按 `05-输出规范与校验表.md` 组装六段结构，按偏好档位裁剪
- **输出**：最终交付物（markdown / table / pdf）
- **约束**：
  - 深挖段落**原文完整引用**，不摘要
  - **但全部数字以数据源为准**——深挖原文中的数字一律不得直接进入结论段与风险段
  - 事件类信息须已由数据源独立确认

### ⑦ 归档修正
- **输入**：本次任务全过程
- **动作**：记录偏差、客户反馈；识别重复出现的反馈模式；给出偏好演进建议
- **输出**：任务归档 + 修正日志条目
- **触发规则**：同一类反馈连续出现 3 次 → 主动建议修改偏好，并说明理由

## 三、粒度控制准则

| 粒度过大（禁止） | 粒度过小（无意义） | 合适粒度 |
|---|---|---|
| "帮我分析整个新能源产业链" | "查一下宁德时代今天收盘价" | "分析宁德时代在动力电池环节的竞争位次" |
| "帮我做一份投资策略报告" | "把这份 PDF 转成表格" | "对比宁德时代与比亚迪的电池业务盈利能力" |

**判定标准**：如果任务的产出无法用"一份可交付物 + 一张校验表"承载，说明粒度过大，需要拆分。


## 四、并行任务处理

客户一次提多个任务时，**拆成多张任务卡**，而不是合并成一张。执行时可并行取数、串行交付。

```
客户："帮我看看宁德时代，顺便把昨天市场也复盘一下"
  ↓
任务卡 20260925-01 · 宁德时代竞争位次分析（研究型，50/50）
任务卡 20260925-02 · 9月24日市场复盘（数据型，深挖 30%）
  ↓
并行取数 → 各自校验 → 分别交付
```


## 五、异常处理

| 异常 | 处理 |
|---|---|
| 深挖报告状态 error | 重试一次；仍失败则交付数据层成果，并说明深挖侧未完成 |
| 深挖轮询超时（>12 分钟） | 告知客户仍在生成，先交付数据层，稍后补交主体部分 |
| 深挖点不足 | 发布前 `user_info` 拦截，提示充值（微信 shenwa4119），不静默失败 |
| 数据源缺数 | 标注「未获取」，不得以估算填补 |
| 客户临时改口径 | 本次覆盖，记录到修正日志，询问是否写入偏好文件 |
