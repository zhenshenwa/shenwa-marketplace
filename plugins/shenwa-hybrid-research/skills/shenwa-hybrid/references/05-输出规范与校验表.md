# 05 · 输出规范与校验表

## 一、交付形态（v1.9.0 新增 · 先定形态，再定结构）

**交付形态由任务深度与问题类型决定，不按内容篇幅**。四种形态：

| 形态 | 何时用 | 必含 | 附深挖全文 | 六段结构 |
|---|---|---|---|---|
| **短答** | 单一事实 / 明确小问题 | 直接回答 + 关键依据 + 必要限制 | ❌ 不附 | ❌ 不用 |
| **比较表** | 两个及以上对象的并列对照 | 对照表 + 口径与截面说明 + 差异归因 | ❌ 不附 | ❌ 不用 |
| **简析** | 数据已足够解释的轻量判断 | 数据 + 简析 + 证据状态 | ⚪ 按需 | ❌ 不用 |
| **完整报告** | 单标的纵深 / 需分析结论的报告类任务 | 六段齐备 | ⚪ 按需（归档仍完整） | ✅ **用六段** |

> 共性要求（**四种形态都适用**）：**关键问题的回答必须完整、重要结论必须有依据、证据不足必须可见**。
> **不得**为了"看起来简洁"而删掉关键依据或限制条件。**形态可以简化结构，不能简化内容**。
> ⚠️ **不按篇幅强制、不做无理由自动回退**（v1.9.0）——旧版"篇幅不匹配即自动回退 50/50 / full"已作废。

## 一·之零 · 完整报告的标准产出结构（六段）

**本节只适用于「完整报告」形态**（单标的纵深、需要分析结论的报告类任务）。六段**是完整报告的一种组织形式**，**不强制用于所有任务**（短答 / 比较表 / 简析不必套六段）。深挖内容集中在第 3 段，数据内容集中在第 2、4 段——**这正是 50/50 配比在结构上的体现**。

```
┌────────────────────────────────────────────────────┐
│ 第 1 段 · 结论摘要          （按偏好口径，3~5 条）    │
│ 第 2 段 · 事实底座          （数据源 100%，硬数据）   │
│ 第 3 段 · 分析主体        （归档件照录，剔除确认错误）  │
│ 第 4 段 · 校验表            （数据源 100%，逐项核对） │
│ 第 5 段 · 风险与情景        （深挖 + 数据源共同支撑） │
│ 第 6 段 · 数据溯源与免责    （全量来源与时点）        │
└────────────────────────────────────────────────────┘
  深挖贡献 ≈ 第 3 段 + 第 5 段主体 ≈ 50%
  数据源贡献 ≈ 第 2 段 + 第 4 段 + 第 6 段 ≈ 50%
```

## 一·补 · A 档 · 结构化直取档（v1.3.0 新增，豁免六段结构）

> **触发条件**：任务的**指标族 = 右侧状态**（右侧 / 阶段 / 迁移 / 否决 / 资格），且深度为**名单 / 分布**（Q0.9 判定；如"哪些行业出现了右侧确认"）。
> ⚠️ **不是**「所有横截面任务」——**乖离率 / 估值 / 财务比较各自进入适配能力**（S8·D9 / D1·D7 / D2），不适用本档。
> **本档不适用上面的一~三节**：不写分析结论、不套六段结构、不做深挖正文校验表、**不发布任何深挖报告**。

**标准产出 = 四张表 + 计数**：

| 表 | 数据来源字段 | 附注列 |
|---|---|---|
| **升级名单** | `state_trans.transition_type == "Upgrade"` | `prev_state → curr_state`、`q_pass_days` |
| **破坏名单** | `state_trans.transition_type == "Breakdown"` | `prev_state → curr_state`；**跳级（如 S1→S5）须标注** |
| **临界名单** | `state.qualification_summary.q_overall == "near"` 或 `state_trans.q_pass_days > 0` | `q_overall` |
| **否决名单** | `state.veto_check.has_veto == true` | `triggered_flags[]` |

**另须随附**：四张表的**计数**、**阶段分布**（S0~S5）、**迁移分布**（Hold / Upgrade / Breakdown）。

**A 档的四条硬规定**：

1. **表头必须标注覆盖范围**——按**本次实际返回**填写（实测：深挖右侧确认框架覆盖的精选池为 **62 个行业与主题指数**，须注明该口径来源），**覆盖数量不得写死**；**不得**写成"全市场所有概念"；四类名单**存在重叠，不得相加**当作覆盖总数。
2. **分桶口径唯一**：一律以 `state_trans.transition_type` 为准；`state_mapping.state_action` 是**单标的自身口径**，**不用于迁移分桶**。
3. **成本必须为 0 点**：本档走 `get_right_side` 直取（0 点、秒级）。若产生点数，说明误发了报告，须复盘。
4. **结构化字段不免检（v1.4.0 修正，取代原「等同行情数据、可直接使用、无需二次校验」）**：红线管深挖**报告正文**的叙述性数字；但 `get_right_side` 的字段**不因"是接口原始输出"而免检**。所见数据分**三层**——**观测数据**（接口直给字段）/ **计算指标**（按公式算出）/ **模型判定**（深挖的状态、阶段、否决、迁移）；本地质量检查**只作用于前两层**，**模型判定照录不改判、不另造阶段标准**（字段业务含义 S0~S5 须引自 `skills/shenwa/SKILL.md` 的实测记录）。必做本地检查：**先按目标日期切截面**再统计；日期与代码唯一性、覆盖数量、重复记录、未知状态、**否决字段三态**。⚠️ **否决字段缺失 / None / 解析失败 ≠ 无否决**；**空结果、明确业务失败 ≠ 无异常**。

> **两段式**：若客户既要名单、又要解读，第 1 段用本档出名单（0 点），第 2 段只对 top-N（默认 1~3）**另开标准档任务卡**（5 点/标的）。两段不混在一张卡里。

> **A 档自检清单**（替代第五节的六段自检）：
> - [ ] 已标注覆盖范围（按**本次实际返回**，注明口径来源；**未写死数字**）
> - [ ] 已跑数据质量门（切截面 / 唯一性 / 覆盖 / 重复 / 未知状态 / **否决三态**）
> - [ ] 四类名单**未相加**当作覆盖总数
> - [ ] 四张表齐备 + 计数 + 阶段分布 + 迁移分布
> - [ ] 分桶口径统一（`transition_type`）
> - [ ] 否决项附 `triggered_flags[]`
> - [ ] **未发布任何深挖报告**，成本 0 点
> - [ ] 无权限时如实告知（未偷偷退回逐标的发报告）
> - [ ] **覆盖范围是否按实报、并区分「已检查」与「已独立验证」**（v1.5.0）
> - [ ] **「Breakdown = 0」未写成结构健康**（须同时报 S5 存量占比与否决率）

## 一·补二 · 数据口径与字段约定（v1.4.0 新增 · 进入分析前的前置 = 校验「轮 0」）

> **适用全部档位**（标准档与 A 档）。口径没统一之前，任何比对都是在造伪偏差。

### 1. 最小必要字段约定

每条进入分析的数据都必须能回答下列 9 项；**缺失就记「未知」，不得补造、不得猜默认值**：

| 字段 | 含义 | 例 |
|---|---|---|
| 对象标识 | 代码 / 名称 / 代码+名称 | `300750.SZ 宁德时代` |
| 指标定义 | **必须含口径** | `ROIC(TTM)`、`资产负债率(合并口径)` |
| 数值 | 原始数值 | `8.37` |
| 单位 | %、亿元、倍、点、个 | `%` |
| 所属期间 | 2026H1 / 2026Q2 / 2026FY / TTM / 2026-09-30 | `TTM` |
| 公开或生效时间 | 披露日 / 生效日 | `2026-08-28` |
| 取数时间 | 本次实际取数时刻 | `2026-09-26 14:03` |
| 来源 | D1~D8 / S11 / 深挖 | `D2` |
| 处理方法 | raw 原始 / computed 计算 / derived 推导（可附公式） | `computed(总负债/总资产)` |

### 2. 必须区分的五组口径

| 组 | 不可混用的两面 | 混用的后果（实测） |
|---|---|---|
| 期间 | **半年度 / 全年 / 单季 / TTM** | 拿 H1 营收直接比 FY 营收 → 凭空造出近 50% 伪偏差；FCFF 单季 −1.83 亿 vs 年度 461.58 亿 |
| 均线 | **MA 与 EMA** | 同一标的一边"跌破 EMA20"、一边"仍在 MA20 上方"，结论方向相反 |
| 表现 | **绝对表现与相对表现** | 把"跑赢行业的幅度"当作"自身涨幅" |
| 量纲 | **指标水平与变化量** | PCB 乖离率**水平 −0.44%** 与**当日变化 −4.47 个百分点**被正文与表格混用 |
| 单位 | **百分比(%) 与百分点(pct/pp)** | "上升 2%" 与 "上升 2 个百分点" 在不同基数下差值可达数倍 |

### 3. 先可比性，再差异

1. **先**判可比性（对象 / 指标口径 / 期间 / 单位 / 均线族 / 表现口径 / 量纲）；
2. **不可比** → **不得**计算相对偏差，改为**并列呈现 + 说明分歧来源**（口径差异导致的方向相反**不算拦截级**）；
3. **可比** → 才计算相对偏差，且**分母统一取基准值**。

### 4. 零 / 近零 / 符号变化 / 不可比的明确处理

| 情形 | 处理 |
|---|---|
| 基准为 0 | **不输出比例**，只给绝对差，判定标「不可用比例判定」 |
| 基准接近 0 | 输出比例但标记「基准接近 0」，**不机械套 1%/5%/50% 阈值**，须人工判断 |
| 符号变化 | 比例无方向意义，**以绝对差（百分点）为准** |
| 口径不可比 | 不计算比例，并列 + 归因 |

### 5. 金额与单位、比例复算、摘要与表格一致性 —— 都要跑程序

`skills/shenwa-hybrid/scripts/data_qc.py` 是**唯一实现**，直接用，不要另写：

```bash
python3 skills/shenwa-hybrid/scripts/data_qc.py selftest              # 内置真实数值自检
python3 skills/shenwa-hybrid/scripts/data_qc.py records <记录.json>   # 字段完整性 + 金额单位 + 可比性门 + 偏差
python3 skills/shenwa-hybrid/scripts/data_qc.py checks  <清单.json>   # 数据驱动的检查清单
```

覆盖：① 字段完整性；② **金额与单位**（单位缺失 / 10·100·1000·10000 倍量级可疑）；③ **比例复算**（恒等式 比率 = 分子 / 分母）；④ **摘要与表格一致性**（同一指标在结论摘要与数据表内必须同值）。

> **恒等式冲突时的措辞纪律**：发现「总资产 7588.80 / 总负债 7249.26 / 资产负债率 63.65%」这类内部不一致时，
> 程序会算出**隐含比率 95.53%** 并标冲突 —— 但**不得**直接宣布 95.53% 是真实资产负债率：
> 分子或分母本身可能就是错的（口径错配 / 单位错 / 取错科目）。**三个原值 + 来源全部保留，交人工复核。**

### 6. 数据冲突的处理纪律

**保留原值和来源 → 标记冲突 → 不擅自选一个数充当真值。** 冲突项进校验表并置顶提示，不并入"已核对"。

## 一·补三 · 证据采信与交付范围（v1.5.0 新增 · 进入成稿前的最后一道门）

> **适用全部档位。** 本节的目的是让**最终结论的确定程度与实际证据一致**，
> 并消解「深挖原文必须全文保留」与「已确认错误必须剔除」的**规则冲突**。

### 1. 归档层与正文层分开（冲突的正面解法）

| 层 | 规则 | 内容 |
|---|---|---|
| **原始资料层**（归档件） | **完整保留全文**：不摘要、不改写、不省略章节 | **含已确认错误的段落**；保留**报告编号（aid）/ 生成时间 / 来源（模板 tid、站点）**。⚠️ **任何交付形态下归档都完整保留**（v1.9.0）；正文是否附全文随形态——短答 / 比较表不附，简析 / 完整报告按需附，未附时**另给归档入口** |
| **研究层**（正文） | 只呈现本轮**认可的事实、推断、假设与局限** | 已确认错误的原文**不得继续支持正文结论**；如需展示须标 `role=error_contrast`（错误对照），且**不得进入结论摘要** |

> 两条规则**作用对象不同**，因此不冲突。字面冲突时一律判为「**归档保留全文 + 正文禁用**」。
> 规则优先顺序：**接入合规 > 归档完整性 > 正文采信 > 证据状态标注 > 结论确定程度 > 交付范围**。

### 2. 证据五态（「有来源」≠「已独立核实」）

| 状态 | 含义 | 能否作「已确认事实」 |
|---|---|---|
| `verified` | 已取得、口径明确，**且已独立核实** | ✅ 可以 |
| `unverified` | 已取得、口径明确，但**未独立核实** | ❌ 只能**按来源转述并写明限制** |
| `conflict` | 已取得但**存在冲突** | ❌ **并列原值与来源**，不给单一判断 |
| `pending` | **待验证** | ❌ 加限定 |
| `missing` | **缺失** | ❌ 不得使用 |

> ⚠️ 「某报告说站上均线比例 88.68%」——这只是**取到了**，不等于**核实了**。
> 未独立核实前，**不得**在摘要中以已确认事实据此判断「广度健康」；可改为
> 「据 XX 报告（2026-09-30），站上均线比例 88.68%；**该数字尚未独立核实**」。

### 3. 结论 ↔ 证据对应（失效即动作）

| 关键证据状态 | 对结论的动作 |
|---|---|
| 全部 `verified` | **保留明确结论**（不要无故模糊化） |
| 存在 `unverified` / `pending` | **降低确定程度**（加「尚未独立核实」等限定） |
| 存在 `conflict` | **改写**为并列呈现原值与来源 |
| 存在 `missing` | **撤回**该结论 |
| 关键证据**全在时间窗口之外** | **标为历史背景**，不计入本窗口新增证据 |

### 4. 三条容易踩的口径陷阱

| 陷阱 | 正确做法 |
|---|---|
| 用**乖离率**未创新低去断言某个**价格**支撑位未破 | **不行**。乖离率是价格相对均线的偏离，**不含前低价信息** → 只能表述为「乖离率未见新低」并注明该指标不覆盖前低 |
| 用「相对跑赢」否定「绝对下跌」 | **不行**。相对表现与绝对表现**量纲不同，可同时成立**（跑赢一个下跌的基准，自身仍可下跌） |
| 未确认对象 / 时间窗口 / 基准 / 指标就横向比较 | **先确认四项一致**，不一致则并列说明，**不得直接比较** |

### 5. 资料不足、统计口径与覆盖率

| 项 | 规则 |
|---|---|
| 资料不足 | **交付能完成的部分** + 说明**覆盖范围、缺项及其影响**；样本不完整时**不得**输出没有样本依据的总体百分比 |
| 有限样本 | **不得**写成「市场 / 卖方整体共识」 |
| 统计 | 必须有**样本量 / 分母 / 去重规则 / 时间口径**；引用他人报告统计须**保留归属**，**不得**改写成本包自行统计 |
| 覆盖率 | **「已检查覆盖率」≠「已独立验证覆盖率」**，两者分别报告；不得把校验表全部条目都算成「已验证」 |

### 6. 交付状态阶梯（不得越级）

`生成中` → `已生成未校验` → `部分校验` → `已校验` → `研究已验证完成`

> ⚠️ **深挖报告生成成功 ≠ 研究已验证完成。** 只有关键证据全部独立核实**且**覆盖完整，才可写「已校验」。

### 7. 实现入口

```bash
python3 skills/shenwa-hybrid/scripts/evidence.py selftest                  # 内置真实场景自检
python3 skills/shenwa-hybrid/scripts/evidence.py archive <report.json>     # 归档 vs 正文
python3 skills/shenwa-hybrid/scripts/evidence.py support-level --bias b.json [--price-low p.json]
python3 skills/shenwa-hybrid/scripts/evidence.py delivery <request.json>   # 交付范围收缩
python3 skills/shenwa-hybrid/scripts/evidence.py assemble <case.json>      # 端到端 + 一致性自检
python3 skills/shenwa-hybrid/scripts/evidence.py checks <清单.json>        # 数据驱动检查清单
```

### 第 1 段 · 结论摘要
- 3~5 条，每条一句话结论 + 一句依据
- 表述口径严格服从 `conclusion_bias`：
  - `conservative` → 用"具备条件但需验证""尚不构成充分理由"等审慎表述
  - `neutral` → 并列利弊，给出条件式判断
  - `aggressive` → 明确方向性判断，附触发条件
- **不得**在此段出现未经校验的数字

### 第 2 段 · 事实底座
- 由数据源产出，以表格为主
- 按能力类别分块：行情与估值 / 财务 / 资金 / 公告事件 / 同业对标
- 每个数字必须标注**来源 + 截取时点**
- 格式示例：

| 指标 | 数值 | 同比 | 来源 | 截取时点 |
|---|---|---|---|---|
| 收盘价 | 000.00 | +0.00% | D1 | 2026-09-25 15:00 |
| 营收(TTM) | 0,000 亿 | +00% | D2 | 2026H1 |
| 主力净流入 | +00.0 亿 | — | D3 | 2026-09-25 |

### 第 3 段 · 分析主体
- 深挖报告原文**完整归档**（归档件**不摘要、不改写、不省略章节**，**含已确认错误的段落**）
- **正文是否附全文随交付形态**（v1.9.0）：短答 / 比较表不附；简析 / 完整报告按需附。
  **未附时必须在正文给出归档入口**（aid + 生成时间 + 来源 + 本地归档路径），归档件始终完整
- 若报告极长，可加导航目录，但归档件必须完整
- 段落开头注明：模板名、**生成时间、深挖报告编号（aid）、来源**

## 一·补六 · 多维需求与交付门（v1.11.0 新增 · 交付前的最后一道门）

### 1. 问题清单是交付的对照物

用户一次提出的**每个问题**都登记为一行（编号 / 原话 / 对象 / 时间 / 事实·计算·解释 / 指标族 / 证据 / 执行方式 / 状态 / 回答位置）。
⚠️ **问题数量 ≠ 指标族数量**：同一指标族可含多个问题，一个问题也可跨多个指标族；**不得按指标族合并问题**。

### 2. 执行方式按证据缺口选（不是按「分析」二字、也不是按族数）

| 执行方式 | 触发条件 | 是否发布报告 |
|---|---|---|
| `direct_fetch` | 已有可用接口能满足的事实查询 | **否**（直接取数） |
| `compute` | 能由已有数据算出的量 | **否**（直接计算，保留口径） |
| `existing_material` | 现有资料足以支撑的分析 | **否**（用现有资料完成） |
| `report_candidate` | 存在**实质证据缺口**、需进一步研究、**且模板能力匹配** | 是（**进入报告候选**） |
| `blocked` | 有缺口但**无匹配模板能力** | **否**（如实列出缺口） |

> 一个任务**可组合**多种执行方式；**「出现分析二字」「命中两个以上指标族」都不是发报告的理由**。

### 3. 交付门：覆盖情况 vs 完成情况（**必须分开记录**）

| 维度 | 含义 | 判定 |
|---|---|---|
| **覆盖情况** | 每个问题是否**被登记并处理**，有无静默遗漏 | 逐题核对问题清单；有未登记的问题 = 覆盖不通过 |
| **完成情况** | 是否**已有足够证据并实际完成回答** | 分 `answered` / `partial` / `unfinished` 三态 |

- **未完成**时必须写明**具体原因与缺少的材料**（合法原因：`material_insufficient` / `calibre_incomparable` / `no_authorization` / `submit_unknown` / `out_of_scope` / `capability_unavailable` / `not_implemented_yet`）。
- **「缺资料」不算完整回答，不得用其他问题的结论代替**。
- **存在未完成的必需问题时，整体任务不得标记为「全部完成」**。
- 该检查进入**实际交付流程**（`scripts/requirement.py` 的 `deliver_gate()`），不得只写在任务卡或自查文档里。


## 一·补七 · 发布计划与预算（v1.12.0 新增 · 发布前的最后一道闸）

### 1. 发布计划：条目编号 + 与问题清单的对应

每份拟发布的报告登记为一个**条目**，至少记录：**条目编号 / 所属任务与问题编号 / 研究对象 / 模板与本次用途 /
为什么需要新报告（现有资料还缺什么）/ 研究截止时间与输入材料 / 拟提交参数 / 历史报告候选与复用检查状态 /
预计成本与成本依据 / 执行状态与 aid / 结果引用**。

- **一份报告可支持多个问题，一个问题也可需要多份报告** —— 对应关系必须明确，**不得默认「一家公司等于一份报告」**。
- **报告份数由模板能力、具体问题、有效复用共同决定**；完整研究 8 家时，**8 个对象 × 用户要求的问题 × 研究深度都要覆盖**，
  **不得以报告份数代替任务完成度**，**也不得静默缩减为 3 家**。
- **直取 / 计算 / 已有资料足够的问题不建条目** —— 不为凑齐计划而新增报告。

### 2. 五项检查（`gate()`）与真实入口

| 检查 | 判据 | 不通过时 |
|---|---|---|
| ① 必要性 | 有明确用途 + 可查的实质证据缺口 | `no_publish`（**提交次数 0**） |
| ② 历史报告状态 | 三态之一（见 §3） | `unknown` **不冒充**「无候选」，仍须必要性与授权 |
| ③ 计划覆盖 | 计划覆盖用户已列出的全部报告候选问题 | `confirm_required`（先补计划） |
| ④ 授权与预算 | 在已授权范围内 + 额度够（**只读预检**） | `confirm_required`（条目转 `pending_authorization`） |
| ⑤ 参数一致性 | 对象 / 模板 / 输入材料 / 提交参数与计划一致 | `confirm_required` + **重新检查** |

- **第 1 轮参数校验仍在 `Client.call()` 内层生效**，`gate()` **不吞不改**。
- **入口是 `publish_plan.publish()`** —— **只有 `proceed` 才真的调 `report_publish`**；
- 「检查剩余额度 + 预留本次成本」在 `BudgetLedger.reserve()` 内**原子完成**。

### 3. 复用检查：查询三态 **都不是「可复用」** + 内容判定四档（v1.13.0 起）

**查询三态**（回答「有没有候选」，**都不是「可复用」**）：

| 状态 | 含义 |
|---|---|
| `no_candidate` | 成功查询且无候选 —— **仍须**必要性与授权；**不得**写成「已确认没有可复用报告」 |
| `candidate_unverified` | 存在候选但**尚未核实内容** —— 不得标成「已经复用」，也不得标成「无候选」 |
| `unknown` | 查询失败或结果未知 —— **不得**冒充「无历史报告」，**也不得**把查询失败当成生成新报告的理由 |

**内容判定四档**（v1.13.0 起由 `scripts/reuse.py` 按**内容六查**给出，**不看列表 / 标题 / 模板 / 日期**）：

| 判定 | 含义 | 对发布计划 |
|---|---|---|
| `full_reuse` | 完整复用 —— 六项核查全通过，内容满足当前问题、关键条件仍适用 | `reuse_all` → **不发布**（复用内容**进入该问题的证据与回答**，**不只是取消发布**） |
| `partial_reuse` | 部分复用 —— 已覆盖当前问题但仍有未核实项，或跨日仅时效数据失效、稳定部分仍成立 | `reuse_partial` → 条目**收窄到剩余缺口**后仍发布 |
| `reference_only` | 仅作历史参考 —— 未回答当前问题，或保留原时间·事实·判断更合适 | **不免除研究**，条目照常 |
| `not_applicable` | 不适用 / 待核实 —— 报告未完成·不可读、用户明确要求新时点 / 新情景 / 重做等 | **不免除研究**，条目照常 |

> 六项核查 = 对象与层级 / 是否真正回答当前问题 / 研究截止时间是否适用 /
> 关键假设·情景·输入材料是否仍成立 / 报告是否完成且可读 / 关键证据及校验状态是否满足当前用途。
> **任一项未知 → 不得判为完整复用**；**用户明确要求新时点 / 新情景 / 重做 → 一律不适用**（不得用旧报告替换）。

### 4. 预算与消耗的口径

- 三分：**已结算消耗** / **尚未结算的预留占用** / **拟新增**；**已结算不再计入预留**。
- **账户余额 ≠ 用户允许本次全部花费的额度**；**数量提醒阈值不自动缩减研究范围**，也不替代预算检查。
- **预计成本 = Σ(条目模板成本)**，来源 = `templates` 接口 `data[].templates[].cost`；
  **成本未知 → `unknown`，不按 0 处理**。
- 模板估价只用于**估算**，**只有获得扣点依据才标「实际消耗」**。
- 已授权范围内**不再逐份询问**；超出时**只暂停受影响的未发布条目**，保留完整任务与待执行事项。

### 5. 状态与 aid

- 状态：`pending` / `pending_authorization` / `submitting` / `accepted` / `done` / `failed` / `submit_unknown`；
  预留状态：`none` / `reserved` / `settled` / `released` / `unknown`。
- **aid 只代表服务端受理**：**不等于报告完成，更不等于用户问题已回答**。
- 结果未知 → **保留占用、不换站重发**；**只有确认未消耗或取得结算依据后才调整占用**。

实现：`scripts/publish_plan.py`（`build` / `gate` / `publish` / `reuse_decision` / `BudgetLedger` / `selftest`）。


## 一·补八 · 背景组装、来源关系与内容复用（v1.13.0 新增 · 让深挖拿到「该拿的背景」）

### 1. 背景组装：从「随手写一句」到「有据、可核对、可独立理解」

发送给深挖的 `text` **一律经 `publish_plan.assemble_background()` 组装**，
`publish()` 会**保存实际发送的参数与文字**（`sent_params` / `sent_text`）——
**验收查的是实际发送的内容，不是组装函数的输出**。

| 背景种类 | 传送规则 |
|---|---|
| `verified_number` 经核实且影响本次分析的数字 | **可以传入**，**保留来源 / 时间 / 单位 / 口径** |
| `unverified_material` 与任务相关的未核实材料 | 可以传入，**必须标明状态**（「尚未独立核实」） |
| `user_hypothesis` 用户观点 | 表述为**待检验命题**，**不得改写成已确认事实** |
| `existing_judgement` 既有判断 | **解释 / 验证时**可以提供，**注明来源 / 时间 / 用途** |
| `preset_conclusion` 预设结论 | **独立判断当前状态时一律不注入** |

- **只选择本次研究需要的关键背景**；完整材料保留在本地记录中。
- 🔴 **不假设深挖能够读取本地路径 / 文件名 / 内部材料编号** ——
  实际发送的文字必须**能够独立理解**。
- 压缩背景**不得改变**数字 / 单位 / 时间 / 条件 / 核实状态，**不得机械截断**。
- 🔴 **超出 `text` 上限（500 字）**：先丢**显式标为可选**的背景并**如实记录**；
  仍超限 → **必须先调整问题条目或执行方式**，并**重新检查需求覆盖与预算**；
  **不得静默删除关键约束后继续发布**（`gate()` 会以 `confirm_required` + 重新检查拦下）。

### 2. 来源关系：同源 / 复述 ≠ 独立证据

材料 / 来源记录（`MATERIAL_FIELDS`，共 15 个字段、对应 14 项追踪要求）至少能追踪：
**对应对象与问题编号 / 材料或证据编号 / 来源名称与可核对位置 / 材料所属时间·公开或可用时间·获取时间（未知显式标记）/
指标含义·单位·统计口径 / 核实状态 / 属于原始事实·计算结果·外部判断·用户待检验观点 /
与其他材料的引用·转述·底层同源关系**。

- 🔴 **来源关系是补充信息** —— 它回答「这算不算独立证据」，**不能替代**五态证据校验。
- **深挖复述已传入的背景数字，不算新增独立证据**（`echo_check()`）。
- **不同接口引用同一底层材料，不自动算独立验证**（`same_underlying` / `derived_from` 归同源）。
- 关系无法确认 → `unknown`：**不默认独立，也不武断认定同源**。
- **按具体证据判定** —— **不因一处同源就把整份报告的其他证据全部归为同源**。
- **不得仅因两个结果一致，就写成「两路独立验证一致」**（`can_claim_two_way_independent()` 准入）。

### 3. 内容复用：四档判定（**按内容，不按文件名**）

**报告列表 / 标题 / 模板编号 / 对象 / 日期只用于寻找候选**；能否复用**必须检查内容及其依据**：

| 核查项 | 判据 |
|---|---|
| ① 对象与层级 | 与当前任务一致 |
| ② 是否真正回答当前问题 | **语义等价**（不机械比对文字） |
| ③ 研究截止时间 | 是否仍适用（跨日**稳定信息可用、时效数据须重查**） |
| ④ 假设 / 情景 / 输入材料 | 是否仍成立 |
| ⑤ 完成与可读 | 未完成 / 正文不可读 / 关键依据无法核对 → **不得宣称已满足** |
| ⑥ 关键证据与校验状态 | 要作**当前依据**时须达 `verified` |

四档：**完整复用**（作当前依据）/ **部分复用**（剩余缺口继续处理）/
**仅作历史参考**（不冒充当前结论）/ **不适用或待核实**（说明原因，**不把未知写成通过**）。

- **同日、同对象、同模板但研究问题不同 → 不得直接复用**。
- 表述不同而问题相同、内容充分 → **可以复用**。
- 旧结论依赖**已变化的数据** → **必须重新分析**，**不得只替换数字、保留旧结论**。
- 用户**明确要求新时点 / 新情景 / 重新开展研究** → **不得用旧报告替换**。
- **无候选 ≠ 已确认没有可复用报告**（未知不得写成通过）。

### 4. 与发布计划 / 预算 / 交付的衔接

- 复用结果**关联问题编号**；**完整复用的内容进入该问题的证据与回答**，**不只是取消发布**。
- **部分复用** → 保留**未解决**的问题，条目**收窄**后仍发布。
- 调整计划后**重新计算预计新增消耗**并**核对已有授权**。
- 历史报告 aid 与本次新发布 aid **分别记录来源与用途**。
- **不得因为后来决定复用，就清除已提交 / 结果未知条目的状态和预算占用**。
- **不得为了降低报告数量而降低研究深度或减少对象覆盖**。
- 最终交付继续区分**已覆盖 / 部分完成 / 全部完成**。

+ `scripts/evidence.py`（`make_material` / `SourceGraph` / `echo_check`）
+ `scripts/publish_plan.py`（`assemble_background` / `recheck_after_reuse` / `run_reuse_flow`）。

## 二、校验表格式

| # | 校验项 | 深挖正文值 | 数据源值 | 偏差 | 判定 | 处理 |
|---|---|---|---|---|---|---|
| 1 | 2025 年营业收入 | 1,234 亿 | 1,236 亿 | 0.16% | 一致 | 采用数据源值 |
| 2 | 当期毛利率 | 21.5% | 20.8% | 3.4% | 轻微偏差 | 采用数据源值，脚注深挖原值 |
| 3 | 全球市占率 | 37% | 32% | 15.6% | 显著偏差 | 双值并列，标注存疑 |
| 4 | 2027 年产能规划 | 500GWh | 未获取 | — | 无法验证 | 保留深挖值，标注未经独立验证 |

### 判定规则

| 偏差 | 判定 | 处理 |
|---|---|---|
| ≤ 客户设定阈值（默认 1%） | 一致 | 采用数据源值 |
| 1% ~ 5% | 轻微偏差 | 采用数据源值 + 脚注标注深挖原值 |
| 5% ~ 50% | 显著偏差 | 双值并列 + 标注「存疑」+ 提示人工复核 |
| **> 50% / 量级错误 / 方向性误判** | **拦截级** | **该数字或结论直接作废，不得进入交付物**；整段依赖它的，整段删除并说明原因 |
| 数据源无对应数据 | 无法验证 | 保留深挖值 + 标注「未经独立验证」 |

**特殊情形（2026-09-25 对照实验新增）**：

| 情形 | 处理 |
|---|---|
| **误报数据缺口**（深挖声称"数据缺失"，但数据源实际有） | 以数据源为准补齐，**覆盖**深挖的缺口声明，不并列 |
| **深挖报告内部自相矛盾**（同一份报告内两处冲突） | 标注为报告缺陷并列入校验表；同时对该报告其余数字**降级采信** |

### 财报类数据以数据源为基准值（v1.1 新增）

**规则**：凡属**财报类数据**——三大报表科目（营收 / 净利 / 毛利率 / 总资产 / 总负债 / 现金流等）、财报衍生指标（同比环比、周转率、负债率、覆盖倍数）、以及由财报科目直接算出的财务比率——**基准值一律取数据源（D2）**。

| 要点 | 说明 |
|---|---|
| 取数入口 | **只能是数据源**；深挖正文中的同类数字**不得作为取数来源** |
| 深挖数字的用途 | 仅用于**发现差异**（填入校验表「深挖正文值」列），不用于形成结论 |
| 是否仍需校验 | 仍需——校验表照旧逐项列出，但判定基准是数据源值 |
| 特别注意 | 财报科目是**最容易出现量级错误**的一类（实测出现过"股价 220 元 vs 实际 84.34 元"），故不设"深挖优先"的例外情形 |

> 与既有规则的关系：这**不改变**「深挖原文完整**归档**」（归档件照录不删），只**收紧取数入口**——归档完整，但**财报数字一律从数据源取**，且**已确认错误的段落不得支撑正文结论**，三者并行不冲突（见 一·补三）。

### 校验必须先做数据源内部一致性

校验分两轮，**顺序不可颠倒**：**轮 1** 数据源内部一致性 → **轮 2** 深挖 vs 数据源。

> 依据：对照实验在数据源内部发现 5 处矛盾（含 2 处 10 倍单位错误、1 处总资产表述错误、1 处口径差 62%、1 处评级分布自相矛盾）。跳过轮 1 会拿错误数据去校验深挖，制造伪偏差。
> 补充（2026-09-26 端到端实跑）：轮 1 另检出 **4 处「同名不同口径」陷阱**——净利率（含少数股东 vs 归母）、ROE（期末 vs 加权）、股息率（TTM vs 最近年度）、FCFF（单季 vs 年度）。若不先做轮 1，会拿 16.98% 去校验 15.63%，凭空造出 8.6% 伪偏差。

### 校验顺序：先验「估值链输入锚点」，再验结论（C13 新增）

深挖的估值结论往往是一条**链**：`当前 PE / PB / 股息率 / ROE / 增长率（输入锚点）` → `估值弹性表` → `DCF / 内在价值` → `目标价区间` → `折价/溢价与安全边际`。

**校验必须从输入端开始，而非从结论端开始**：

```
第 1 步  核验「估值链输入锚点」：当前 PE、PB、股息率、ROE、增长率、FCFF 基期
   ├─ 某锚点偏差 > 5%    →  只作废**真正依赖该锚点**的推演（不再「整链作废」）；
   │                        与该锚点无关的推演照常保留
   │                        （不必去逐个校验 6 个目标价与 4 个弹性系数）
   └─ 锚点全部一致       →  再逐项校验估值结论
```

> 依据（2026-09-26 实跑）：某报告 3 个输入锚点全部失真（PE 18x vs 实际 15.98x、PB 3.2x vs 3.64、股息率 1.2% vs 2.80%），用"偏低的盈利基数 × 偏高的 PE 倍数"推出 DCF 与"折价 15%、安全边际充足"。**把作废范围限定到该锚点的下游，既避免对 6 个目标价与 4 个弹性系数的无谓逐项校验，又不牵连与 PE / PB / 股息率无关的结论（轮次 4 修正）。**

### 深挖报告内部一致性检查（C14 · 固定检查项）

> **改为每份深挖报告的固定检查项**（此前被当作"特定模板的注意项"，实测证明价值型模板同样会出现）。

逐项检查同一份报告内是否存在两处冲突的表述（如"风险情景目标价 -30%"与"悲观情景 -3.6%"并存）。发现即：
1. 标注为**报告缺陷**并列入校验表 D 类；
2. **触发对该报告其余数字的降级采信**；
3. 结论段**不得沿用**冲突结论。

### 结论合理性不得豁免输入校验（C16 · 2026-09-26 新增）

> **规则**：**输入锚点校验是前置强制步骤，不得因结论数字落在合理区间内而跳过。**

深挖的估值结论"看起来对"是**概率事件**；输入锚点是否正确是**可验证事实**。二者必须分别校验。

> 依据（2026-09-26 实跑，最重要的一条）：某报告中性值 ￥345 恰好落在数据源推导的中性区间（293~336）内、其乐观值 ￥448.5 也落在乐观区间内 —— 但它的**三个输入锚点（PE 18x / PB 3.2x / 股息率 1.2%）全部失真**（实际 15.98 / 3.64 / 2.80%）。它是"**用错输入算出了看起来合理的结果**"。
>
> 危害在于参数漂移时的放大效应：一旦假设条件变化（如该报告自己设定的"毛利率下滑 3pct"情景发生），错误锚点会立刻把结论推到区间之外。**若只看结论，会误判该报告为"可用"；只有先做锚点校验（C13），才能识破失真。**

**执行要求**：
1. 校验表中新增 **「输入锚点」独立分区**，位于所有估值结论项之前；
2. 输入锚点（PE / PB / 股息率 / ROE / 增长率 / FCFF 基期）**必须逐项列出「深挖值 vs 数据源值」**，不得合并成一句"估值假设存在偏差"；
3. 锚点分区存在 > 5% 偏差时，**在交付物中显式标注**"该报告的估值推演链因输入失真而作废，本段估值改用数据源独立推导"。

### 多方法差异的解释（C17 修正 · v1.6.0）

> **规则**：**取消「估值结论必须至少两种方法」这一准入条件**——单方法在其**边界内**同样有效（见「一·补四」）。方法齐备时并列呈现，并**解释差异来源**；**不得**因某方法结果偏低或偏离其他方法而剔除它。

**差异是信息，不是错误。** 各方法的输入口径与假设本就不同：

| 方法族 | 依赖的关键假设 | 常见差异来源 |
|---|---|---|
| 绝对法（FCFF / FCFE 折现） | WACC 或股权资本成本 Ke、增长率 g、终值口径 | 折现率与增长率假设的微小变动会被永续项放大 |
| 股息率法 | 分红政策的可持续性、要求股息率 | 分红不稳定或一次性特别分红 |
| 相对法（PE / PB-ROE / PS） | 可比对象的选取与倍数中枢 | 同业/板块口径不同、折溢价修复速度不可知 |

| 差异幅度（离散度 = (最高−最低)/中位) | 含义 | 处理 |
|---|---|---|
| **< 5%** | 结果接近 | 并列输出；**仍不据此宣称准确** |
| **5% ~ 15%** | 存在结构性分歧 | 并列输出 + 标注分歧来源 |
| **> 15%** | 差异显著 | 并列输出 + 逐条解释**各自假设**；**不得**为求收敛删除偏低结果，**不得**静默取平均 |

> 依据（2026-09-26 实跑）：三方法（股息率法 293.4 / PB-ROE 301.2 / 相对 PE 293.9）中性值收敛于 **293~301（差异 < 3%）**，而两阶段 DCF 给出 **335.7（+14.4%）** —— 差异原因清晰可查：**DCF 由假设驱动（WACC 8.5%、增速 15%），且所设 WACC 高于该公司实际 ROIC 8.37%**。**注意：收敛不等于准确**——该报告自身的中性值也曾"碰巧落在"合理区间内，但其输入锚点全部失真（见 C16）。

**执行要求**：
1. 方法齐备时给出**方法矩阵**（方法 × 保守/中性/乐观）与差异解释；方法只有一种时，**只陈述该方法及其边界**，不得为凑数引入输入不足的方法；
2. 必须给出**离散度**与**差异来源**（输入 / 口径 / 时点 / 假设）；
3. ⚠️ **接近程度 ≠ 准确度**；准确度取决于输入是否被独立核实、假设是否被声明、口径是否一致；
4. 输出形态仍受红线约束：**只给区间与触发条件，不给单点目标价。**

### 一·补四 · 估值方法与适用条件（v1.6.0 新增 · 估值段的前置门）

> 本节只解决一件事：**让估值的确定程度与实际证据一致**。它**不**新增估值模型，也不改深挖服务端；实现落在 `skills/shenwa-hybrid/scripts/valuation.py`（本包唯一估值实现）。

#### 1. 现金流与折现率必须配对（口径一致优先于一切）

| 现金流 | 归属资本 | 必须配的折现率 | 折出什么 | 之后还要做什么 |
|---|---|---|---|---|
| **FCFF**（企业自由现金流，**不扣利息**） | 股权 + 有息债权 | **WACC** | **企业价值（经营资产价值）** | 必须走「企业价值 → 股权价值」桥 |
| **FCFE**（股权自由现金流，**已扣利息**） | 仅股权 | **股权资本成本 Ke** | **股权价值**（直接） | 除以总股本即可，**不再减有息债务** |

⚠️ **错配会给出方向性错误的答案**：FCFF 配 Ke（Ke > WACC）→ 分母偏大 → **系统性低估**企业价值；FCFE 配 WACC → **高估**股权价值。错配时**拒绝计算**，先统一口径。

#### 2. 企业价值 → 股权价值：调整项必须逐项列明，缺项只给边界

```
股权价值 = 企业价值 ＋现金及现金等价物 ＋非经营资产 －有息债务
                     －少数股东权益 －优先股权益 ± 其他调整
每股价值 = 股权价值 ÷ 总股本
```

- **必要调整项**：现金及等价物 / 非经营资产（至少一项）、有息债务、总股本。
- 缺必要调整项 → **只回传不完整的中间量并说明边界**（缺债务 → 高估；缺现金 → 低估），**`per_share` 一律为空**，**不得假定为零后仍宣称得到完整每股价值**。
- 次要调整项（少数股东权益 / 优先股 / 其他）未提供 → **按零处理但必须显式声明**；「未提供」与「明确为零」是两件事，必须区分。

#### 3. 永续增长公式的守卫

戈登永续 `V = CF₁ / (r − g)` 在 **g ≥ r** 时**分母 ≤ 0**，会得到 ∞ 或负数，**必须阻止计算**并说明原因，改用「显式预测期 + 终值倍数/清算价值」或修正假设；**不得**把该次计算结果当作估值输出。

#### 4. 输入分三类标注；历史外推一律是预测假设

| 类别 | 标注 | 说明 |
|---|---|---|
| 历史观测值 / 已披露事实 | `[历史观测]` / `[已披露]` | 已发生、可核对 |
| **未来假设** | `[预测假设]` | 面向未来，**必须显式声明**，不得冒充已披露事实 |
| 估计值 | `[估计]` | 须标注口径与不确定度 |
| 计算结果 | `[计算结果]` | 由公式算出，随输入与假设变动 |

**历史 CAGR 用于未来预测时**：必须同时声明 **预测期限 + 适用理由 + 敏感性**，并标为**预测假设**；**永远不得**称为"已验证的未来增长率"。三条缺一即为不齐备。

#### 5. 方法选择：按研究对象与数据条件，不按风格；准入只看必要输入

**取消两处一刀切**（v1.6.0）：

| 取消的规则 | 改为 |
|---|---|
| 原「任务含估值 → D7 为必取项，缺 D7 应拒绝输出价格区间」 | **D7 只是相对估值类方法（相对 PE / PB-ROE / PS）的必要输入**；缺它 → **只停用该类方法**，绝对法照常按边界输出 |
| 原「估值结论必须至少两种方法」 | **齐备必要输入的方法即可输出**，**单方法在其边界内同样有效**；多方法用于解释差异，不是准入条件 |

逐方法检查：**研究对象是否适用** + **必要输入是否齐备**。**某方法输入不足时只停止该方法**，其余方法不受影响；**全无方法齐备时不出数**，只列方法与缺失输入。⚠️ 这与"缺 D7 就不能估值"是两回事。

参考注册表（必要输入 → 输出形态）：

| 方法 | 适用对象 | 必要输入 | 产出 | 边界 |
|---|---|---|---|---|
| FCFF 折现 | 个股 / 单一主体 / 产业集团 | FCFF 预测、WACC、有息债务、现金或非经营资产、总股本 | 股权价值（须经桥接） | 缺债务或现金 → 只给企业价值 |
| FCFE 折现 | 个股 / 单一主体 | FCFE 预测、Ke、总股本 | 股权价值（直接） | 杠杆需相对稳定 |
| 股息率法 | 个股 / 单一主体 | 每股股息、要求股息率 | 每股价值 | 需稳定分红记录 |
| PB-ROE | 个股 / 单一主体 | PB、ROE、要求回报 | 每股价值 | 跨行业不可直接比较 |
| 相对 PE | 个股 / 单一主体 | 每股收益、可比倍数 | 每股价值 | 无可比对象即不适用 |
| PEG | 成长型主体 | PE、增速（**预测假设**） | 匹配度判断 | 不给价格 |
| PS | 亏损期成长主体 | 每股营收、可比 PS | 每股价值 | 不可替代盈利能力分析 |

#### 6. 估值异常的作用范围

**某个输入异常只作废真正依赖它的推演**：把结论按「依赖哪些输入」登记，命中异常输入的那几条**撤回 / 改写 / 降确定程度**，其余**照常保留**。⚠️ **不得因某个无关指标偏差而废弃整份报告**，也**不再**「任一锚点偏差即整链作废」。

#### 7. 历史材料：不覆盖，另建修订版

`examples/` 下既有文件属**已发布历史材料，保持原样**。发现错误时**另建修订版本**（新文件名带版本号，如 `<NN>-<主题>-修订-<版本>.md`），并在修订版开头写明：**对应旧版的文件名 + 旧版的具体问题 + 本版改了什么 + 本版与旧版并存、不覆盖**。

---

### 校验覆盖要求
- **强制核对项**：营收、净利润、毛利率、估值倍数、市占率、产能/产量、订单金额
- **比例要求**：正文中出现的可验证数字，校验覆盖率应达 100%；确实无法取得的，必须在表中列出并标注原因

## 三、深度档位裁剪规则

| 段落 | `brief` 摘要式 | `standard` 标准 | `dd` 尽调级 |
|---|---|---|---|
| 1 结论摘要 | ✅ 3 条 | ✅ 3~5 条 | ✅ 5~8 条 + 关键假设 |
| 2 事实底座 | ⚪ 仅核心 5 项 | ✅ 完整 | ✅ 完整 + 多期对比 |
| 3 分析主体 | ✅ **仍须完整** | ✅ 完整 | ✅ 完整 |
| 4 校验表 | ⚪ 仅强制项 | ✅ 完整 | ✅ 完整 + 交叉验证 |
| 5 风险与情景 | ⚪ 仅风险清单 | ✅ 完整 | ✅ 完整 + 敏感性分析 |
| 6 数据溯源 | ⚪ 简表 | ✅ 完整 | ✅ 完整 + 附录 |

> **红线**：无论哪个档位，**归档件（深挖分析主体）一律完整保留**；**正文**呈现随交付形态（见第一节）——短答 / 比较表正文可不附全文，但**必须给归档入口**。裁剪只作用于数据段和推演段，不作用于归档件。

## 四、格式与语言约定

| 项 | 约定 |
|---|---|
| 货币 | 默认 ¥（人民币）；港币 HK$、美元 US$ 需显式标注 |
| 涨跌色 | 遵循中国市场惯例：**涨红跌绿** |
| 数字 | 千分位分隔；金额单位统一（亿/万亿），避免混用 |
| 时点 | 全篇统一到日，行情类精确到分钟 |
| 语言 | 按 `output.language`；`bilingual` 时结论摘要与风险段双语，其余保持中文 |

| 命名 | 交付文件命名：`<任务编号>_<标的>_<任务类型>_<YYYYMMDD>` |
| 格式转换 | **不得改变**结论、数字与验证状态（v1.9.0）；markdown / table / xlsx 之间互转须逐字带出结论与数字 |
| PDF 标注 | 深挖官方原文 PDF → 标为「**原始报告**」；专家包**综合版** PDF → 当前环境**不支持生成**，须说明并交付 markdown / table / xlsx（v1.9.0） |
