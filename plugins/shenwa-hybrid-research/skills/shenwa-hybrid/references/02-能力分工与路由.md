# 02 · 能力分工与路由

## 一、深挖侧能力清单（Shenwa API）

深挖提供**分析主体**，是模式下深度内容的第一来源。全部通过 API 访问，任何情况下不得使用浏览器抓取。

| 编号 | 能力 | 对应接口 | 权限 | 在模式中的用途 |
|---|---|---|---|---|
| S1 | 深度报告生成 | `POST /api/manage/wfStartPublish` | 全部 | 主力能力。按模板异步生成结构化报告（3~10 分钟） |
| S2 | 报告详情读取 | `GET /api/home/getDetail` | 全部 | 读取报告全文，**原文完整引用，不摘要** |
| S3 | 报告状态轮询 | `GET /api/home/getReportStatus` | 全部 | 确认生成完成（public/private/error） |
| S4 | 模板列表 | `GET /api/manage/getTemplateListWithType` | 全部 | 按任务类型匹配模板，决定报告深度 |
| S5 | 报告列表 | `GET /api/home/getList` | 全部 | 查公共/私有/收藏，复用历史研究 |
| S6 | PDF 下载 | `GET /api/home/downloadPdf` | 全部 | 交付 PDF 版时优先直接下载已排版文件 |
| S7 | 报告收藏 | `POST /api/home/doArticleAction` | 全部 | 沉淀高价值报告到收藏库 |
| S8 | 乖离率数据 | `GET /api/review/getGuailiRates` | VIP2 | 情绪与择时辅助 |
| S9 | 知识库检索 | `POST /api/data/knowledgeSearch` | VIP2 | 新闻、脱水券商研报、卖方报告检索 |
| S10 | 用户信息 | `GET /api/user/getUser` | 全部 | 发布前检查深挖点余额与有效期 |

**深挖承担的边界**：逻辑推演、驱动因素拆解、竞争格局判断、趋势与情景推演、事件影响链条、政策含义解读、风险清单、结论表述。

**深挖不承担的边界**：实时行情、精确财务数字、股东结构明细、逐笔资金流——这些一律交由数据源（D1~D4），且深挖正文中的同类数字**按分层采信规则处理**（见 `01-模式总纲` 红线 1）。

### 接口实操注意事项（2026-09-25/26 实测）

| # | 事项 | 说明 |
|---|---|---|
| 1 | **`text` 字段实际为必填** | 官方文档标注"可选"，实测为错。完全缺省 `text` 会返回 `status=SRV` + `msg=Missing required parameters`，发布失败。**每次发布都必须带一段有意义的背景消息。** |
| 2 | 空串 `text` 会走另一条管线 | 传 `text:""` 能成功，但 aid 前缀变为 `ManualArticle@@<hash>`，与正常路径 `ManualNews@@<hash>@@<时间戳>` 不同，产出可能不一致。**不要用空串占位。** |
| 3 | `aid` 含 `@@` 分隔符 | 形如 `ManualNews@@<hash>@@<时间戳>`。用 sed/grep 截取时易只取到第一段，**必须整串保存与传递**。 |
| 4 | 状态接口有两处 `status` | 响应含顶层 `"status":"SUC"` 与 `data.status` 两个同名字段，**须取后者**，否则会把"生成中"误判为已完成。 |
| 5 | 可高并发发布 | 实测 4 份并发（间隔 4 秒）与 11 份并发均正常，无失败。轮询可在同一循环内统一探测。 |
| 6 | **发布回执的 `stocks` 恒为 null（C10）** | `wfStartPublish` 回执中 `stocks` **始终为 null**，它是**报告生成结果字段**，仅完成后在 `getDetail`/`getList` 中填充。**层级拦截必须改为发布前的静态 tid 映射**，不可依赖回执。 |
| 7 | **轮询「调用异常」≠「报告失败」（C11）** | 只有 `data.status == "error"` 才是失败；超时/非 JSON/5xx 属调用异常，须重试+退避，不得计入状态。实测曾连续 15 轮异常而报告实际已 52 秒完成。 |
| 8 | **耗时可相差 10 倍以上（C12）** | 同为个股级模板：tid=9 为 52 秒；tid=1001 首测 >13 分钟、复测 2.5 分钟。慢生成 ≠ 失败，轮询上限须用 **40 次 / 20 分钟**。 |

**主站降级**：`www.shenwa.top` 在当前环境不可达（HTTP 000），备用站 `8.130.17.247:8088` 自动接管。切换无需人工确认，符合设计。

数据源提供**事实底座与校验层**。泛指非深挖的金融数据与选股类 skill，按能力类别抽象，不绑定具体实现。

| 编号 | 能力类别 | 模式中的用途 | 环境内可映射的 Skill（示例） |
|---|---|---|---|
| D1 | 行情与估值 | 价格、涨跌、市值、PE/PB/PS、估值分位 | westock-data |
| D2 | 财务报表 | 三表关键科目、同比环比、财务指标 | westock-data / neodata-financial-search |
| D3 | 资金流向 | 主力/北向/龙虎榜、成交结构 | westock-data |
| D4 | 公告与事件 | 公告、分红、股东变动、重大事项 | westock-data / neodata-financial-search |
| D5 | 研报与舆情 | 卖方评级、研报观点、新闻舆情 | neodata-financial-search |
| D6 | 标的筛选 | 按条件/策略/标签批量选股选基 | westock-tool |
| D7 | 宏观与行业数据 | 宏观指标、行业经营数据、产业链图谱、**板块估值分位** | wb-finance-skill / westock-data |
| D8 | 结构化整理 | 数据清洗、透视、表格与图表生成 | sheetagent |

**映射原则**：编号 D1~D8 是**能力契约**，不是固定 API。客户环境换了数据源，只要满足该能力类别的输入输出契约，路由层无需改动。这是模式可移植的关键。

### D7 是「能否独立估值」的开关（C15 · 2026-09-26 新增）

| 情形 | 能力 | 处理 |
|---|---|---|
| **无 D7**（无板块分位 / 无同业对标） | 只能做绝对估值（股息率法、DCF），缺横向锚点 | **应拒绝输出价格区间**，只陈述绝对估值敏感度，并如实声明局限 |
| **有 D7** | 可做**相对估值交叉验证**（PE 折价修复、PB-ROE 同业对照），与绝对估值形成方法矩阵 | **可输出收敛区间 + 触发条件**（仍不给单点目标价） |

> 实测依据：上一轮端到端实跑因未取 D7，模式**如实拒绝**输出目标价；补取 D7（锂电池概念板块 PE 26.673/分位 37.98%、PB 2.7618/分位 57%，及比亚迪/亿纬/国轩/欣旺达同业数据）后，**四方法收敛并给出区间**（中性 293~336 元）。
>
> **执行要求**：`04-SOP` 第 ④ 步中，**任务含估值 / 目标价 / 合理区间结论时，D7 为必取项**。

## 三、路由决策树

> **路由顺序：先定层级 → 再定类型 → 后定比例。**
> 标的层级的优先级高于任务类型：**个股层级的任务不得指派板块级或行业级模板**。
> （此条为 2026-09-25 对照实验 P3 组的实测教训：个股趋势问题被路由到板块监测模板，产出主体变成板块指数，个股仅在一节内被回应。）

```
收到任务
  │
  ├─ Q0：标的层级是什么？【优先级最高，不可跳过】
  │     ├─ 个股 / 单一主体  → 仅可指派个股级能力
  │     ├─ 板块 / 行业      → 指派板块级或行业级能力
  │     ├─ 产业链           → 指派产业链级能力
  │     └─ 宏观 / 跨市场    → 指派宏观级或事件级能力
  │
  ├─ Q1：任务是否只需要「事实/数字」，不需要判断？
  │     是 → 【数据型】数据源主导（深挖 0~20%）
  │     否 ↓
  │
  ├─ Q2：任务核心是「市场数据加工」还是「逻辑判断」？
  │     ├─ 市场数据加工为主 → 【数据型】数据源主导（深挖 20~30%）
  │     └─ 逻辑判断为主 ↓
  │
  ├─ Q3：标的是「单个主体」还是「多主体/行业」？
  │     ├─ 单主体 → 【研究型】深挖 50%，数据源 50%（公司深度研究）
  │     └─ 多主体/行业 → 【研究型】深挖 50%，数据源 50%（行业对比）
  │
  ├─ Q4：任务是否由「外部突发事件/政策」驱动？
  │     是 → 【研究型】深挖 55~60%，数据源 40~45%
  │     否 → 回退基准 50/50
  │
  └─ Q5：所选模板的标的层级是否与 Q0 一致？（详见下方模板全量表）
        个股层级 → 仅可在 {0,1,7,8,9,10,2001} 中选；禁用 3002（板块级 + 重体量）
        板块层级 → 3002 / 3001
        行业层级 → 4 / 5 / 6
        产业链   → 3 / 11
```

### Q0.5 · 板块级任务的「指数口径确认」步骤（C18 · 2026-09-26 新增）

> **背景（实测）**：板块级任务里，「板块」二字对应的指数往往不止一个，且**权重结构差异极大**，会直接导致同一问题得出**方向相反**的答案。

> **实测案例**：2026-09-26「PCB 板块处于技术面右侧哪个阶段」任务——
> - 深挖 tid=3002 采用 **932666.CSI 中证印制电路板指数**（34 只成分股，前三大权重 39.13%、前十大 **73.82%**，龙头集中型）→ 判定「已跌破 EMA20」→ **S5 右侧结构破坏**
> - 数据源侧 `pt02101284 PCB 概念`（231 只，高度分散）→ **仍在 MA20 上方 +3.99%**
> - 二者**数字都准确**（深挖称「连续 16 个交易日站上均线」，与独立复算的 16 日完全吻合），分歧 100% 来自**权重结构**：9/24 十大权重股全线下跌、加权 -4.23%，深于板块整体 -3.11% —— 龙头口径必然更弱。

**执行规则**：板块级任务在 ④ 并行取数前，**必须完成口径确认**：

```
Q0.5 指数口径确认
  ├─ 先问：本任务用哪个"板块"定义？是否存在多个候选指数？
  │    （如 PCB：中证印制电路板指数 932666.CSI ≠ PCB 概念 pt02101284）
  ├─ 取两个口径的权重结构数据（成分股数、前三大/前十大权重占比）
  ├─ 若两口径关键结论**方向相反** → 不在交付物中择一，
  │    必须**双口径并列 + 归因到权重结构**，并给出「看龙头 vs 看广度」的实务含义
  └─ 交付物与任务卡中**显式标注所用指数代码与全称**，禁止只写"XX板块"
```

**判定要点**：口径差异导致的**方向相反**，**不算拦截级**（拦截级要求"无口径差异下的方向性误判"），不得作废任一方；正确做法是并列呈现并解释分歧来源，写入「风险与情景」段。

1. 模板体量高度集中在 1,400~3,300 字，**tid=3002 是唯一的重体量模板**（4,761 字，为次长者的 1.44 倍）。因此不必维护四级体量体系，"重体量预警"实际等价于"禁用 3002"。

### 层级校验：静态前置拦截 + 完成后动态复核（2026-09-26 修正）

> **C10 修正（重要）**：原设计写的是「**发布后**读返回记录的 `stocks`」，**实测证明执行不了** —— `wfStartPublish` 的发布回执里 `stocks` **恒为 null**。`stocks` 是**报告生成结果字段**，只有报告完成后才在 `getDetail` / `getList` 记录中填充（见第 2 次端到端实跑：tid=9 发布回执为 null，完成后为 `宁德时代,300750,积极,A`）。

因此层级校验拆成**两道**：

```
第 1 道 · 静态前置拦截【发布前，有效】
  按 Q5 的「模板-层级静态映射」直接拦截，不依赖任何接口返回：
    - 个股任务 → 禁止选 tid=3002（板块级+重体量）
    - 个股任务 → 禁止选 tid=12（stocks 恒为 null，市场/事件级）
    - 板块/产业链任务 → 必须选对应层级的模板
  命中即重选模板，不消耗生成。

第 2 道 · 动态完成后复核【报告完成后，兜底】
  获取 getDetail / getList 记录中的 stocks 挂载数：
    ├─ 任务为「个股」而挂载数 > 2  → 层级错配，告警
    ├─ 任务为「板块/产业链」而挂载数 < 3 → 层级错配，同上
    ├─ stocks 为 null → 市场/事件级，不得用于个股任务
    └─ 一致 → 继续
```

**代价说明（诚实记录）**：动态复核**只能在生成完成后进行**，因此层级错配无法完全避免浪费一次生成（首轮实验 P3 组就是读完产出才发现的）。**真正的防线是第 1 道静态拦截**——它靠 tid 静态映射，不依赖接口返回，发布前即可生效。第 2 道仅作兜底与告警。

## 四、并行取数约定

深挖报告生成是**异步**的（3~10 分钟）。因此取数必须并行，不能串行等待：

```
T+0min    ├─ 深挖：提交报告发布（异步）
          └─ 数据源：同步拉取 D1~D8 所需数据
T+0min   └─ 静态层级前置拦截：按 Q5 静态映射确认模板层级无错配
T+0~3min  数据源完成取数与整理，形成「事实底座」
T+0~20min 轮询深挖报告状态（详见下方探测节奏；须区分「调用异常」与「报告 error」）
完成后    ├─ 读取深挖报告全文
          ├─ 动态层级复核：读 getDetail.stocks 挂载数（发布回执里该字段恒为 null）
          └─ 逐项核对正文中的可验证数字 → 生成校验表
```

### 轮询探测节奏（2026-09-26 修正）

**C11 修正（重要）：轮询"调用异常" ≠ "报告失败"**。实测中脚本曾连续 15 轮返回异常，但报告实际**早已完成**（发布后 52 秒）——异常来自高频轮询触发的服务端瞬时抖动，事后连续 6 次探测 6/6 正常。若把异常当作失败处理，会**误判报告失败并空转到上限**。

```
状态解析规则：
  data.status ∈ {inprogress, public, private, error}
        └─ 只有 data.status == "error" 才是报告失败
  调用异常（超时 / 非 JSON / 5xx）→ 不计入 status，走「重试 + 退避」
        ├─ 连续 5 次调用异常 → 切换主站/备用站重试
        └─ 仍失败 → 上报「无法获取状态」，不得报「报告失败」

探测间隔（C12 修正）：
  前 2 分钟   → 每 10 秒探测（短耗时模板最快 52 秒即可完成，30 秒轮询会白等）
  2 分钟以后  → 每 30 秒探测
  上限        → 40 次 / 20 分钟
```

**耗时口径（2026-09-26 两次实跑修正）**：原预估"3~10 分钟"偏乐观。

| 模板类型 | 实测耗时 |
|---|---|
| 轻 / 中体量（个股、事件、概念、日报类） | **52 秒 ~ 5 分钟** |
| 关键词跟踪类（tid=3001） | **8~13 分钟** |
| 重体量（右侧区间监测 tid=3002） | 5.5 分钟 |

**耗时抖动**：同为个股级模板，tid=9 实测 **52 秒**完成；tid=1001 首测 **>13 分钟**未完成、复测 2.5 分钟。**同量级模板耗时相差 10 倍以上**，抖动来自服务端排队 / 冷启动，而非模板固有耗时。

**必须向客户明示**：一般 **1~5 分钟**，个别模板可能**超过 10 分钟**，不要假装实时完成；在等待期间先交付数据层进度。**轮询上限 24 次（12 分钟）已被实测证伪**，须用 40 次（20 分钟），否则会把服务端抖动造成的正常慢生成误判为超时失败。

## 五、冲突处理规则

校验分**两轮**，顺序不可颠倒：

```
轮 1  数据源内部一致性校验   ← 先做，通过的数据才能作为轮 2 的基准
轮 2  深挖正文 vs 数据源      ← 后做
```

> **为什么必须先做轮 1**：2026-09-25 对照实验在数据源内部发现 5 处矛盾（含 2 处 10 倍单位错误）。若跳过轮 1，会拿错误数据去"校验"深挖，反而制造伪偏差。

### 轮 2 · 深挖 vs 数据源的判定规则

| 偏差幅度 | 判定 | 处理方式 |
|---|---|---|
| ≤ 1%（或客户设定的阈值） | 一致 | 采用数据源值，标注时点 |
| 1% ~ 5% | 轻微偏差 | 采用数据源值，脚注标注深挖原值 |
| 5% ~ 50% | 显著偏差 | 双值并列，标注「存疑」，提示人工复核 |
| **> 50%，或量级错误，或方向性误判** | **拦截级** | **该数字/结论直接作废，不得进入交付物；整段依赖它的，整段删除并说明原因** |
| 数据源无对应数据 | 无法验证 | 保留深挖值，明确标注「未经独立验证」 |

**两类特殊情形（本次实验新增）**：

| 情形 | 处理 |
|---|---|
| **深挖误报数据缺口**（声称"数据缺失"，但数据源实际有） | 以数据源为准补齐，并**覆盖**深挖的缺口声明，**不并列** |
| **深挖报告内部自相矛盾**（同一份报告中两处数字/表述冲突） | 标注为报告缺陷，列入校验表；同时触发对该报告其余数字的**降级采信** |

**口径冲突**（例如深挖判断"景气上行"而资金流向持续净流出）：

- 不做简单否定，改为**并列呈现 + 解释分歧来源**，写入「风险与情景」段落；
- 若客户偏好为 `conclusion_bias: conservative`，则默认采信更审慎的一方，并标注取舍理由。

## 六、能力指派速查

| 客户想要 | 深挖做 | 数据源做 |
|---|---|---|
| 这家公司值不值得看 | 逻辑链、驱动拆解、竞争位次判断 | 财务三年数据、估值分位、机构持仓、公告事件线 |
| 这个行业格局怎么变 | 格局推演、产业链卡位、趋势判断 | 行业经营数据、代表公司对标表、政策文件清单 |
| 昨天市场发生了什么 | 定调与主线归纳 | 指数涨跌、板块资金、涨跌家数、龙虎榜 |
| 这条政策意味着什么 | 政策含义、传导链条、受益受损判断 | 相关板块当日表现、历史同类政策后的市场反应 |
| 帮我筛一批标的 | 提供筛选逻辑与维度建议 | 按条件批量筛选、输出候选清单与关键指标 |
| 帮我核对这份报告的数字 | 无需介入 | 逐项取数比对，输出校验表 |
