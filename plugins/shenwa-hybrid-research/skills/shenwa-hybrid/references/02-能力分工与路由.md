# 02 · 能力分工与路由

## 一、深挖侧能力清单（Shenwa API）

深挖提供**分析主体**，是模式下深度内容的第一来源。全部通过 API 访问，任何情况下不得使用浏览器抓取。**登录只需注册手机号（userID），不需要邀请码、不需要密码——不要向使用者索要邀请码。**

| 编号 | 能力 | 对应接口 | 权限 | 在模式中的用途 |
|---|---|---|---|---|
| S1 | 深度报告生成 | `POST /api/manage/wfStartPublish` | 全部 | 主力能力。按模板异步生成结构化报告（3~10 分钟） |
| S2 | 报告详情读取 | `GET /api/home/getDetail` | 全部 | 读取报告全文，**完整归档，不摘要**（归档层；进正文另有采信规则，见 05 的一·补三） |
| S3 | 报告状态轮询 | `GET /api/home/getReportStatus` | 全部 | 确认生成完成（public/private/error） |
| S4 | 模板列表 | `GET /api/manage/getTemplateListWithType` | 全部 | 按任务类型匹配模板，决定报告深度 |
| S5 | 报告列表 | `GET /api/home/getList` | 全部 | 查公共/私有/收藏，复用历史研究 |
| S6 | PDF 下载 | `GET /api/home/downloadPdf` | 全部 | 交付 PDF 版时优先直接下载已排版文件 |
| S7 | 报告收藏 | `POST /api/home/doArticleAction` | 全部 | 沉淀高价值报告到收藏库 |
| S8 | 乖离率数据 | `GET /api/review/getGuailiRates` | VIP2 | 情绪与择时辅助 |
| S9 | 知识库检索 | `POST /api/data/knowledgeSearch` | VIP2 | 新闻、脱水券商研报、卖方报告检索 |
| S10 | 用户信息 | `GET /api/user/getUser` | 全部 | 发布前检查深挖点余额与有效期 |
| **S11** | **右侧确认结构化数据** | `GET /api/market/getRightSide` | **ADM / VIP2** | **横截面直取通道（v1.3.0 新增）**。一次调用返回官方精选池全量（**实测 60 余个**行业与主题指数；**交付时按本次实际返回标注，不写死**）的阶段 / 迁移 / 否决 / 资格字段，**0 点、秒级**、不需发布报告。**对象层级 = 板块 / 行业指数（指数级），不是个股**。仅用于「右侧状态」类横截面任务（见 Q0.9 / C19），**不替代单板块纵深解读** |
| S12 | 报告删除 | `GET /api/home/deleteArticle` | 全部 | 移除自己发布的报告。**删除彻底性无证据**，不得据此承诺「服务端不保存」 |

**深挖承担的边界**：逻辑推演、驱动因素拆解、竞争格局判断、趋势与情景推演、事件影响链条、政策含义解读、风险清单、结论表述。

**深挖不承担的边界**：实时行情、**财报类数据（三大报表科目、财报衍生指标、同比环比、财务比率）**、股东结构明细、逐笔资金流、**技术指标（均线 / MACD / RSI / KDJ / 布林带等派生量）**——这些一律交由数据源（**D1~D4、D9**）取数。⚠️ **财报类数据的第一来源是数据源（D2）**：深挖正文中出现同类数字时**仅作对照物**，不得反过来当作取数来源（见 `01-模式总纲` 红线 1）。

### 接口实操注意事项（2026-09-25/26 实测）

| # | 事项 | 说明 |
|---|---|---|
| 1 | **`text` 字段实际为必填** | 官方文档标注"可选"，实测为错。完全缺省 `text` 会返回 `status=SRV` + `msg=Missing required parameters`，发布失败。**每次发布都必须带一段有意义的背景消息。** |
| 2 | 空串 `text` 会走另一条管线 | 传 `text:""` 能成功，但 aid 前缀变为 `ManualArticle@@<hash>`，与正常路径 `ManualNews@@<hash>@@<时间戳>` 不同，产出可能不一致。**不要用空串占位。** |
| 3 | `aid` 含 `@@` 分隔符 | 形如 `ManualNews@@<hash>@@<时间戳>`。用 sed/grep 截取时易只取到第一段，**必须整串保存与传递**。 |
| 4 | 状态接口有两处 `status` | 响应含顶层 `"status":"SUC"` 与 `data.status` 两个同名字段，**须取后者**，否则会把"生成中"误判为已完成。 |
| 5 | 可高并发发布 | 实测 4 份并发（间隔 4 秒）与 11 份并发均正常，无失败。轮询可在同一循环内统一探测。 |
| 6 | **发布回执的 `stocks` 恒为 null（C10）** | `wfStartPublish` 回执中 `stocks` **始终为 null**，它是**报告生成结果字段**，仅完成后在 `getDetail`/`getList` 中填充。**层级拦截必须改为发布前的静态 tid 映射**，不可依赖回执。 |
| 7 | **轮询「调用异常」≠「报告失败」（C11）** | 只有 `data.status == "error"` 才是失败；超时/非 JSON/5xx 属调用异常，须重试+退避，不得计入状态。实测曾连续 15 轮异常而报告实际已 52 秒完成。 |
| 8 | **耗时可相差 10 倍以上（C12）** | 同为个股级模板：tid=9 为 52 秒；tid=1001 首测 >13 分钟、复测 2.5 分钟。慢生成 ≠ 失败，轮询上限须用 **40 次 / 20 分钟**。 |
| 9 | **本地参数校验在发布之前（v1.10.0）** | `report_publish` 的 `tid` / `question` / `text` 由 `shenwa_api.Client.call()` 内的 `validate_params()` 校验；越界在**发请求前**被拦下（不消耗发布）。`question` ≤60 字、`text` ≤500 字、`tid` 必须是字符串 |
| 10 | **`text` 必填性：官方与实测冲突** | 官方 `required:false`；实测缺省失败。本地**不把合法可选参数统一改成必填** → 只告警不阻断，以 `PUBLISH_TEXT_REQUIRED=False` 登记 |

**三档标注（v1.10.0 新增）**：上表每条按**证据强度**分档，避免把经验固化成不准确的规则。

| 档位 | 含义 | 本表例 |
|---|---|---|
| **接口约定** | 官方配置 / 文档**明文** | `question` 不可多于60字、`text` 不可多于500字 |
| **特定条件下实测** | 我们在**某时点 / 某权限 / 某参数**下实测到的行为 | 缺省 `text` 返回 SRV；空串走 `ManualArticle@@` 管线；`dayOffset` 有效 1~20；`tid` 必须是字符串 |
| **待验证推断** | **尚未取得证据**，仅为合理推测 | 服务端按码点还是按字节计数；并发上限；`text` 是否被真正采纳 |

- 只有「**接口约定**」可直接写成规则；「特定条件下实测」**必须写明条件与日期**；「待验证推断」**不得写成规则**。
- **一次记录不是永久保证**：单次请求失败**不自动等于**发布成功或已扣点；单次耗时、单次并发成功也**不是永久保证**。
- **长度口径（v1.10.0）**：本地按 **Unicode 码点数**（`len()`）计、**不 strip**；服务端实际计数方式属**待验证推断**。

**主站降级**：`www.shenwa.top` 在当前环境曾不可达（HTTP 000），备用站 `8.130.17.247:8088` **自动接管；切换无需人工确认**，符合设计。
**接入方式（v1.1 明确）**：深挖**只通过 API 访问**，禁止浏览器抓取；登录**只需注册手机号（userID）**，**不需要邀请码、不需要密码**——不要向使用者索要邀请码。

## 二、数据源侧能力清单（泛金融数据 Skill）

数据源提供**事实底座与校验层**。泛指非深挖的金融数据与选股类 skill，按能力类别抽象，不绑定具体实现。

| 编号 | 能力类别 | 模式中的用途 | 环境内可映射的 Skill（示例） |
|---|---|---|---|
| D1 | 行情与估值 | 价格、涨跌、市值、PE/PB/PS、估值分位 | westock-data |
| D2 | 财务报表 ⭐ **财报类数据的第一来源**（v1.1 起强制优先） | 三表关键科目、同比环比、财务指标 | westock-data / neodata-financial-search |
| D3 | 资金流向 | 主力/北向/龙虎榜、成交结构 | westock-data |
| D4 | 公告与事件 | 公告、分红、股东变动、重大事项 | westock-data / neodata-financial-search |
| D5 | 研报与舆情 | 卖方评级、研报观点、新闻舆情 | neodata-financial-search |
| D6 | 标的筛选 | 按条件/策略/标签批量选股选基 | westock-tool |
| D7 | 宏观与行业数据 | 宏观指标、行业经营数据、产业链图谱、**板块估值分位** | wb-finance-skill / westock-data |
| D8 | 结构化整理 | 数据清洗、透视、表格与图表生成 | sheetagent |
| **D9** | **技术指标**（v1.7.0 新增） | 均线、乖离率、MACD / RSI / KDJ / 布林带 / ATR、量能等**由行情派生的指标** | westock-data |

**映射原则**：编号 **D1~D9** 是**能力契约**，不是固定 API。
> ⚠️ **编号口径（v1.7.0 统一）**：原文档里 `D4` 同时代表「公告与事件」「技术指标」两种数据能力（模板里把技术指标写成了 D4），另有偏好选项组也用 `D` 字母（D4 = 可视化）。现统一为：**D1~D8 含义不变**，**新增 D9 = 技术指标**，**偏好选项组 `D` 更名为 `F`**。完整清单与九项属性见 `references/09-能力清单.md`（由 `scripts/capability.py` 生成）。客户环境换了数据源，只要满足该能力类别的输入输出契约，路由层无需改动。这是模式可移植的关键。

### D7 只是「相对估值类方法」的必要输入（C15 修正 · v1.6.0）

**取消原文的「开关」表述**：D7 不是「能否估值」的总开关，它只是**部分方法**的必要输入。判定改为**逐方法检查「必要输入 + 适用条件」**。

| 方法族 | 是否依赖 D7 | 缺 D7 时的处理 |
|---|---|---|
| 相对估值（相对 PE / PB-ROE / PS） | **是**（需要可比倍数或板块估值分位） | **只停用该类方法**，并如实说明缺可比对象 |
| 绝对估值（FCFF / FCFE 折现、股息率法） | **否**（只需自身的财务与假设输入） | **照常按该方法边界输出**（如缺债务/现金 → 只给企业价值，不给每股价值） |

> 依据（2026-09-26 实跑 + 轮次 4 修正）：上一轮端到端实跑因未取 D7 而**拒绝输出任何价格区间**，这一处理**过宽**——当时绝对估值（DCF）的输入其实齐备，完全可以在边界内输出「企业价值 + 假设敏感度」，只是不能做相对估值交叉验证。补取 D7（锂电池概念板块 PE 26.673/分位 37.98%、PB 2.7618/分位 57%，及比亚迪/亿纬/国轩/欣旺达同业数据）后，相对法加入，**四方法并列并解释差异**（中性 293~336 元）。
>
> **执行要求**：`04-SOP` 第 ④ 步中，取数**按任务所含方法族的必要输入**决定；含相对估值类方法时才需要 D7。方法选择**按研究对象与数据条件**，不按用户风格强制。

## 二·补 · 路由顺序与能力边界（v1.7.0 新增）

### 1. 六步识别顺序（**不可颠倒**）

```
① 研究问题   → 事实 / 机制 / 比对 / 筛选 / 状态
② 对象与范围 → 对象层级（红线，优先级最高）+ 数量 → **数量只产出「批量方式」**
③ 指标       → 指标族（**唯一的「选哪个能力」依据**）
④ 时间范围   → 绝对 / 相对 / 前瞻 / 当前截面
⑤ 所需深度   → fact / state / list / comparison / deep_research
⑥ 可用能力   → 按权限与状态过滤；`unverified` / `unavailable` **不得承诺**
```

> **为什么把「指标」放在第三步、而不是把「词语」放在第一步**：旧路由用
> 「排名 / 有没有 / 三个以上对象」这类**词语**直接决定走哪条通道，于是
> 「比较三家公司的盈利质量」与「哪些板块发生右侧升级」会被塞进同一条路。
> 现在**词语只影响批量方式**，**选哪个能力只由指标族决定**。

### 2. 十条硬规则（v1.7.0 五条 + v1.11.0 增补两条 + v1.12.0 一条 + v1.13.0 一条 + v1.14.0 一条）

| # | 规则 | 反例（旧行为） |
|---|---|---|
| 1 | 「**排名 / 哪些 / 有没有 / 三个以上**」**只影响批量方式**，永不决定分析类型 | 见「哪些」就判横截面、就进直取通道 |
| 2 | **`get_right_side`（S11）只用于「右侧状态」**；乖离率 → S8 / D9，估值 → D1 / D7，财务比较 → D2 | 把乖离率、估值、财务比较也塞进右侧扫描 |
| 3 | **单对象可直取；多对象可深入分析**；数据足够解释时用「**数据 + 简析**」，不强制另发报告 | 只要不是名单就必须发报告 |
| 4 | 模板选择与回退都要**重查 对象层级 / 主题 / 指标 / 时间**；**不得无条件把复杂任务转给 2001**（2001 是**个股级**） | 一遇复杂就转 2001，把行业/板块任务降级成个股模板 |
| 5 | **排名 / Top-N 必须说明排序标准**；关键歧义先澄清，否则用**透明默认**并写明 | 直接给一个「值得看」的榜，不说按什么排 |
| 6 | **多维需求一条不丢**（v1.11.0）——**问题数量 ≠ 指标族数量**，同一指标族可含多个问题；**不得按指标族合并问题**，路由命中多族**全部保留** | 只按优先级取第一个指标族，用户其它问题静默丢失 |
| 7 | **执行方式按证据缺口选**（v1.11.0）——直取 / 计算 / 现有资料 / 报告候选 / 如实列缺；**「出现分析二字」与「命中两个以上指标族」都不触发报告**，也都不触发改选 2001 | 见「分析」二字就发报告、族多就转 2001 |
| 8 | **每次发布都要有明确用途与任务对应**（v1.12.0）——报告发布一律经 `publish_plan.publish()` 真实入口；条目编号**提交前生成**并绑定 aid；**成本未知不按 0**、**余额 ≠ 授权额度**、**aid ≠ 报告完成 ≠ 问题已回答** | 随手调 `report_publish`、按返回顺序认领 aid、把模板估价写成已扣点 |
| 9 | **背景要有据 · 来源要判独立 · 复用要看内容**（v1.13.0）——背景经 `assemble_background()` 组装并**记录实际发送文字**（核实数字带来源·时间·单位·口径、未核实标状态、用户观点写待检验命题、独立判断不注入预设结论、**不假设深挖能读本地路径**、超限**不静默截断**）；**复述 / 同源不得充作独立证据**（关系未知标 `unknown`）；历史报告**按内容**判四档复用（**同日同对象同模板但问题不同不得直接复用**、跨日时效数据须重查、旧结论依赖已变数据必须重新分析） | 拿旧报告当现成答案、把复述当第二路验证、超限偷删关键约束 |
| 10 | **监测要留档 · 比较要在成稿前**（v1.14.0）——持续跟踪 / 与上次或指定日期比较 / 检验更新此前判断 / 属于已建立监测序列的任务，一律经 `monitor.run_monitor_flow()` 真实入口；**首次监测从本次建立基线，不编造历史变化**；基线**指定优先、其次最近适用**（**不按文件修改时间 / 下载顺序 / 返回顺序**）；**读取失败 ≠ 无历史**；**先检查可比性再算变化**（口径差异不直接归因对象变化、缺失值不当 0、基数 0 不硬算、状态按迁移比较）；**数据修订 / 规则调整不写成研究对象变化**；**两个时点不称持续趋势**；**重复归档不制造新观测**（原始不覆盖、修订 `supersedes` 保留原始值）；**资料足够不新增发布**；**未接入真实调度** | 现场拍「环比上升」、把口径调整写成业务变化、两点连成「趋势」、重复归档当新观测 |

### 3. 对象数量只影响「批量方式」

| 批量方式 | 触发条件 | 影响 |
|---|---|---|
| `single` | 1 个对象 | 直取 |
| `few` | 2 个对象 | 逐个直取或并列 |
| `cross_section` | ≥3 个对象 / 「全市场·所有行业·一片」 | 走批量通道（**但用哪个能力仍由指标族决定**） |

> ⚠️ 「批量方式」**只是执行形态**（一次取一个 vs 一次取一批），
> **不改变分析类型、不改变交付深度、不改变研究问题**。

### 4. 能力边界（摘要）

完整清单见 `references/09-能力清单.md`。要点：

- 状态四态：`verified_supported` / `conditional` / `unverified` / `unavailable`；
  **未验证 ≠ 不存在，但不能直接承诺支持**。
- **权限硬门槛**：S8 / S9 / S11 需 **VIP2**（S11 还需 ADM），无权限返回 `status=AUT` → **如实告知**。
- **本地保存 ≠ 服务端「公开 / 私有」**：`wfStartPublish` **无可见性参数**，
  故**不得承诺「私有发布」**；发布即入库，故**不得承诺「服务端不保存」**。
- **量化 / 回测 / 跨市场**：只有画像名称 ≠ 完整具备；**回测为 `unavailable`**，跨市场为 `unverified`。

## 三、路由决策树

> **路由顺序（v1.7.0 起固定为六步，不可颠倒）**：① 研究问题 → ② 对象与范围 → ③ **指标族** → ④ 时间范围 → ⑤ 所需深度 → ⑥ 可用能力。
> 标的层级的优先级高于任务类型：**个股层级的任务不得指派板块级或行业级模板**。
> **「发不发报告」由「深度」决定**（`fact` / `state` → 直取或「数据 + 简析」；`list` → 直取名单；`comparison` / `deep_research` → 发报告）。
> **`get_right_side`（S11）只在「指标族 = 右侧状态」时使用**——横截面语汇本身不构成走该通道的理由。
> （此条为 2026-09-25 对照实验 P3 组的实测教训：个股趋势问题被路由到板块监测模板，产出主体变成板块指数，个股仅在一节内被回应。）

```
收到任务
  │
```

### Q0.5 · 板块级任务的「指数口径确认」步骤（C18 · 2026-09-26 新增）

> **背景（实测）**：板块级任务里，「板块」二字对应的指数往往不止一个，且**权重结构差异极大**，会直接导致同一问题得出**方向相反**的答案。

> **实测案例**：2026-09-26「PCB 板块处于技术面右侧哪个阶段」任务——
> - 深挖 tid=3002 采用 **932666.CSI 中证印制电路板指数**（34 只成分股，前三大权重 39.13%、前十大 **73.82%**，龙头集中型）→ 判定「已跌破 EMA20」→ **S5 右侧结构破坏**
> - 数据源侧 `pt02101284 PCB 概念`（231 只，高度分散）→ **仍在 MA20 上方 +3.99%**
> - 二者**数字都准确**（深挖称「连续 16 个交易日站上均线」，与独立复算的 16 日完全吻合），分歧 100% 来自**权重结构**：9/24 十大权重股全线下跌、加权 -4.23%，深于板块整体 -3.11% —— 龙头口径必然更弱。

**执行规则**：板块级任务在 ④ 并行取数前，**必须完成口径确认**：

```
Q0.5 指数口径确认
  ├─ 先问：本任务用哪个"板块"定义？是否存在多个候选指数？
  │    （如 PCB：中证印制电路板指数 932666.CSI ≠ PCB 概念 pt02101284）
  ├─ 取两个口径的权重结构数据（成分股数、前三大/前十大权重占比）
  ├─ 若两口径关键结论**方向相反** → 不在交付物中择一，
  │    必须**双口径并列 + 归因到权重结构**，并给出「看龙头 vs 看广度」的实务含义
  └─ 交付物与任务卡中**显式标注所用指数代码与全称**，禁止只写"XX板块"
```

**判定要点**：口径差异导致的**方向相反**，**不算拦截级**（拦截级要求"无口径差异下的方向性误判"），不得作废任一方；正确做法是并列呈现并解释分歧来源，写入「风险与情景」段。

### Q0.8 · 执行方式初判（v1.11.0 新增）

### Q0.9 · 结构化直取通道（C19 · 2026-09-30 新增；**v1.7.0 判据改版**）

> ⚠️ **v1.7.0 适用边界收窄**：本通道**只服务「指标族 = 右侧状态」**（右侧 / 阶段 / 迁移 / 否决 / 资格）。
> **乖离率 → S8 / D9，估值 → D1 / D7，财务比较 → D2** —— 它们即使也是横截面、也要「排名 / 名单」，
> 也**不得**走本通道（v1.6.0 及以前按「多标的横截面」一刀切，是错的）。
> **对象数量只决定批量方式**：`cross_section` → `codes` 留空；`few` → 逐个指定。

> **背景（实测）**：原路由只有「标的层级」与「任务类型」两个维度，**缺「数据形态」**。于是「找右侧确认的行业和概念」会被拆成「一个板块一份 tid=3002 报告」——**成本随标的数线性膨胀**，本质上不成立。

**两条路径的实测对比**：

| 对比项 | tid=3002（右侧区间监测助手） | `get_right_side`（接口直取） |
|---|---|---|
| 覆盖范围 | 单次一份报告，实测挂载 **10 个标的**（单一板块内） | **一次 GET = 官方精选池全量**（**实测 62 个**行业与主题指数；**交付按本次实际返回标注，不写死**） |
| 产出形态 | 4,761 字**叙述性报告**（全量模板里唯一"重体量"） | **结构化 JSON**（阶段 / 迁移 / 否决 / 资格字段） |
| 耗时 | 实测 **5.5 分钟**（须发布 + 轮询） | **秒级** |
| 成本 | **5 点 / 次** | **0 点** |
| 扫全量精选池 | 需 **N 次发布**（N 随标的数增长） | **1 次调用** |

> 一句话：用 3002 做全市场扫描，相当于**用显微镜数星星**——每一次都准确，但根本不成立。

**两类任务的本质差异**（**判据是指标族，不是对象数量**）：

| | **单标的纵深（右侧状态）** | **右侧状态族 · 横截面** |
|---|---|---|
| 典型问法 | 「PCB 板块现在处于右侧哪个阶段」 | 「**哪些**行业出现了右侧确认」 |
| 要什么 | 成因、推演、判断 | **名单、排名、计数、分布** |
| 交付物 | 一份报告（或「数据 + 简析」） | 四张表 |
| 成本结构 | 每标的 × 5 点 | 全量 × **0 点** |
| 正确路径 | 发模板报告（Q1~Q6 流程）／直取+简析 | **接口直取（本通道）** |
| 反例（**不得**走本通道） | — | 「哪些板块**乖离率**改善最快」「哪些行业**估值**分位较低」「比较三家公司的**盈利质量**」 |

**执行规则**：

```
① 取数：shenwa_api.py get_right_side dayOffset=<1~20>
   - codes 留空 = 官方精选池全量（无需逐个指定；**实测 62 个，交付按实际返回标注**）
   - dayOffset 有效范围实测 1~20（官方写"">1"是错的，1 可用）；缺省 2
   - 每个元素的 data 字段是【再一层 JSON 字符串】，必须二次 json.loads

② 分桶（口径一律以 state_trans.transition_type 为准，不用 state_mapping.state_action）
   - 升级：transition_type == "Upgrade"   → 附 prev_state → curr_state
   - 破坏：transition_type == "Breakdown" → 附 prev_state → curr_state，跳级须标注
   - 临界：qualification_summary.q_overall == "near" 或 state_trans.q_pass_days > 0
   - 否决：veto_check.has_veto == true   → 附 triggered_flags[]

③ 质量门（★ v1.4.0 新增，出表前必做，不得凭人眼）
   - 先按 `date` 切目标截面，再统计；**不得对全量面板直接分桶**
   - 检查：日期与代码唯一性 / 覆盖数量 / 重复记录 / 未知状态 / **否决字段三态**
   - ⚠️ 否决字段缺失、None、解析失败**必须单列**，**不得当作「无否决」**
   - ⚠️ `data == []` 是「空结果」，`success=false` / `status∈{AUT,SRV}` 是「明确失败」，两者分开报
   - ⚠️ 四类名单**存在重叠，不得相加**当作覆盖总数

④ 交付：四张表 + 计数
   - ★ 豁免六段结构、不写分析结论、不发布任何报告（见 05 的「A 档 · 结构化直取档」）
   - ★ 必须显式标注覆盖范围：按**本次实际返回**填写（实测精选池 62 个行业与主题指数，须注明口径来源），**不得写死数字**
```

**两段式（直取筛名单 → 纵深读候选）**：当用户既要名单、又要对某些标的做解读时——**同一总任务下的两个子任务，最终统一回答**（不得只做一段）。

```
第 1 段（0 点，秒级）：直取出四张表 → 定出候选名单
第 2 段（按需，5 点/标的）：只对名单里 top-N（默认 N=1~3）发 tid=3002 / 2001
```

> **价值**：把「不确定的广撒网」换成「**先筛后读**」。点数从 `N标的 × 5` 降到 `1~3 × 5`，
> 且第 1 段已经把"该看谁"确定下来了。

**四条边界（必须一并遵守）**：

| # | 边界 | 说明 |
|---|---|---|
| 1 | **结构化字段不免检**（v1.4.0 修正） | 红线管的是「深挖**说了什么**」（报告正文的叙述性数字，实测一致率仅 33%），**但这不代表接口吐出来的结构化字段就不用查**。所见数据分**三层**：**观测数据**（接口直给字段）/ **计算指标**（按公式算出）/ **模型判定**（深挖的状态、阶段、否决、迁移）；本地质量检查只管前两层，**模型判定不改判、不另造阶段标准**。必做：**先按目标日期切截面**再统计；查 日期与代码唯一性、覆盖数量、重复记录、未知状态、**否决字段三态**。字段业务含义（S0~S5）应引自 `shenwa/SKILL.md` 的实测记录，不得自行发明解释。原「等同行情数据、可直接使用、无需二次校验」的表述已作废。 |
| 2 | **覆盖范围按实际返回展示，不写死** | `codes` 留空时覆盖官方**精选池**（实测 2026-09-30 为 **62** 个行业与主题指数）——但交付物写的是**本次实际返回的覆盖数量**（由数据得出），并注明口径来源；**不得写死 62**，**不得**写成"全市场所有概念"（A 股概念板块有数百个）。四类名单（升级/破坏/临界/否决）之间存在**重叠**，**不得相加**当作覆盖总数。 |

4. 两个原"未测"模板（12 / 1001）已补测完成，**覆盖率 17/17**；其首次失败原因均为流程参数问题（日期须动态取、轮询上限须放宽），非数据问题。
5. **择优基准 tid=2001（v1.1 新增）**：2001「智能深度推理」是**按需求自适配分析流水线**的通用型个股模板（轻体量 2,297 字 / 1 个挂载标的 / 5.5 分钟）。它不预设固定分析维度，因此**每次选定 tid 前都要拿它与初选模板比一次**——维度多、需求模糊、初选需拼凑 → 改选 2001；专项性更强的初选（9 / 7 / 8 / 1001 / 3002）→ 保留。**比较结论必须写进任务卡。**
6. **2001 是「个股级」模板（v1.7.0 明确）**：它只挂载 **1** 个标的，因此
   **个股层级**任务才可转 2001；**板块 / 行业 / 产业链 / 宏观层级不得转 2001**
   （否则就是层级错配）。**模板回退时同样适用**：回退必须保持
   **对象层级 / 主题 / 指标 / 时间** 四项不变，四项中任一被改掉 → **不回退**，交付已完成部分。

### 层级校验：静态前置拦截 + 完成后动态复核（2026-09-26 修正）

> **C10 修正（重要）**：原设计写的是「**发布后**读返回记录的 `stocks`」，**实测证明执行不了** —— `wfStartPublish` 的发布回执里 `stocks` **恒为 null**。`stocks` 是**报告生成结果字段**，只有报告完成后才在 `getDetail` / `getList` 记录中填充（见第 2 次端到端实跑：tid=9 发布回执为 null，完成后为 `宁德时代,300750,积极,A`）。

因此层级校验拆成**两道**：

```
第 1 道 · 静态前置拦截【发布前，有效】
  按 Q5 的「模板-层级静态映射」直接拦截，不依赖任何接口返回：
    - 个股任务 → 禁止选 tid=3002（板块级+重体量）
    - 个股任务 → 禁止选 tid=12（stocks 恒为 null，市场/事件级）
    - 板块/产业链任务 → 必须选对应层级的模板
  命中即重选模板，不消耗生成。

第 2 道 · 动态完成后复核【报告完成后，兜底】
  获取 getDetail / getList 记录中的 stocks 挂载数：
    ├─ 任务为「个股」而挂载数 > 2  → 层级错配，告警
    ├─ 任务为「板块/产业链」而挂载数 < 3 → 层级错配，同上
    ├─ stocks 为 null → 市场/事件级，不得用于个股任务
    └─ 一致 → 继续
```

**代价说明（诚实记录）**：动态复核**只能在生成完成后进行**，因此层级错配无法完全避免浪费一次生成（首轮实验 P3 组就是读完产出才发现的）。**真正的防线是第 1 道静态拦截**——它靠 tid 静态映射，不依赖接口返回，发布前即可生效。第 2 道仅作兜底与告警。

## 四、并行取数约定

深挖报告生成是**异步**的（3~10 分钟）。因此取数必须并行，不能串行等待：

```
T+0min    ├─ 深挖：提交报告发布（异步）
          └─ 数据源：同步拉取 D1~D8 所需数据
T+0min   └─ 静态层级前置拦截：按 Q5 静态映射确认模板层级无错配
T+0~3min  数据源完成取数与整理，形成「事实底座」
T+0~20min 轮询深挖报告状态（详见下方探测节奏；须区分「调用异常」与「报告 error」）
完成后    ├─ 读取深挖报告全文
          ├─ 动态层级复核：读 getDetail.stocks 挂载数（发布回执里该字段恒为 null）
          └─ 逐项核对正文中的可验证数字 → 生成校验表
```

### 轮询探测节奏（2026-09-26 修正）

**C11 修正（重要）：轮询"调用异常" ≠ "报告失败"**。实测中脚本曾连续 15 轮返回异常，但报告实际**早已完成**（发布后 52 秒）——异常来自高频轮询触发的服务端瞬时抖动，事后连续 6 次探测 6/6 正常。若把异常当作失败处理，会**误判报告失败并空转到上限**。

```
状态解析规则：
  data.status ∈ {inprogress, public, private, error}
        └─ 只有 data.status == "error" 才是报告失败
  调用异常（超时 / 非 JSON / 5xx）→ 不计入 status，走「重试 + 退避」
        ├─ 连续 5 次调用异常 → 切换主站/备用站重试
        └─ 仍失败 → 上报「无法获取状态」，不得报「报告失败」

探测间隔（C12 修正）：
  前 2 分钟   → 每 10 秒探测（短耗时模板最快 52 秒即可完成，30 秒轮询会白等）
  2 分钟以后  → 每 30 秒探测
  上限        → 40 次 / 20 分钟
```

**耗时口径（2026-09-26 两次实跑修正）**：原预估"3~10 分钟"偏乐观。

| 模板类型 | 实测耗时 |
|---|---|
| 轻 / 中体量（个股、事件、概念、日报类） | **52 秒 ~ 5 分钟** |
| 关键词跟踪类（tid=3001） | **8~13 分钟** |
| 重体量（右侧区间监测 tid=3002） | 5.5 分钟 |

**耗时抖动**：同为个股级模板，tid=9 实测 **52 秒**完成；tid=1001 首测 **>13 分钟**未完成、复测 2.5 分钟。**同量级模板耗时相差 10 倍以上**，抖动来自服务端排队 / 冷启动，而非模板固有耗时。

**必须向客户明示**：一般 **1~5 分钟**，个别模板可能**超过 10 分钟**，不要假装实时完成；在等待期间先交付数据层进度。**轮询上限 24 次（12 分钟）已被实测证伪**，须用 40 次（20 分钟），否则会把服务端抖动造成的正常慢生成误判为超时失败。

## 五、冲突处理规则

校验分**两轮**，顺序不可颠倒：

```
轮 1  数据源内部一致性校验   ← 先做，通过的数据才能作为轮 2 的基准
轮 2  深挖正文 vs 数据源      ← 后做
```

> **为什么必须先做轮 1**：2026-09-25 对照实验在数据源内部发现 5 处矛盾（含 2 处 10 倍单位错误）。若跳过轮 1，会拿错误数据去"校验"深挖，反而制造伪偏差。

### 轮 2 · 深挖 vs 数据源的判定规则

| 偏差幅度 | 判定 | 处理方式 |
|---|---|---|
| ≤ 1%（或客户设定的阈值） | 一致 | 采用数据源值，标注时点 |
| 1% ~ 5% | 轻微偏差 | 采用数据源值，脚注标注深挖原值 |
| 5% ~ 50% | 显著偏差 | 双值并列，标注「存疑」，提示人工复核 |
| **> 50%，或量级错误，或方向性误判** | **拦截级** | **该数字/结论直接作废，不得进入正文；整段依赖它的，在正文中整段删除并说明原因**。⚠️ **归档件照常保留该段落** |
| 数据源无对应数据 | 无法验证 | 保留深挖值，明确标注「未经独立验证」 |

**两类特殊情形（本次实验新增）**：

| 情形 | 处理 |
|---|---|
| **深挖误报数据缺口**（声称"数据缺失"，但数据源实际有） | 以数据源为准补齐，并**覆盖**深挖的缺口声明，**不并列** |
| **深挖报告内部自相矛盾**（同一份报告中两处数字/表述冲突） | 标注为报告缺陷，列入校验表；同时触发对该报告其余数字的**降级采信** |

**口径冲突**（例如深挖判断"景气上行"而资金流向持续净流出）：

- 不做简单否定，改为**并列呈现 + 解释分歧来源**，写入「风险与情景」段落；
- ⚠️ **不得因客户偏好（`conclusion_bias` / `risk_tolerance`）而改判**——偏好只改**呈现顺序与措辞**（审慎 = 先列反面证据），**不改变**采信结论、证据状态与方法适用条件（v1.9.0）。
