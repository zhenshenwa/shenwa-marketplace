# 06 · 客户使用与修正指南

> 本文档面向终端客户。模式维护者请对照本文件设计交付话术。

## 一、安装与启用

```
1. 复制整个 shenwa-hybrid-blueprint 目录到自己的工作区
2. 复制 03-偏好配置模板.yaml → profile.yaml
3. 打开 profile.yaml，填写「最小可运行配置」的 5 个必填字段
4. 保存，开始使用
```

**需要具备的能力**：一个可用的深挖（Shenwa）账号；一个可用的泛金融数据 skill 环境。
**不需要具备的能力**：编程。所有个性化都通过修改 YAML 文本完成。

## 二、首次个性化：只需要决定 5 件事

| # | 字段 | 你要回答的问题 | 选项 |
|---|---|---|---|
| 1 | `identity.primary_style` | 你主要靠什么赚钱？ | 价值 / 成长 / 趋势 / 短线 / 量化 / 主题 |
| 2 | `identity.horizon` | 你看多长？ | 长（3-5 年）/ 中（1-3 年）/ 短（周-季） |
| 3 | `identity.risk_tolerance` | 你能承受多大回撤？ | 保守 / 中性 / 进取 |
| 4 | `identity.conclusion_bias` | 你希望结论怎么说？ | 偏审慎 / 中性 / 偏积极 |
| 5 | `output.depth` | 你要多细？ | 摘要式 / 标准 / 尽调级 |

填完这 5 项，模式即可运行。其余字段（数据权重、关注池、校验阈值）可在使用中逐步调优。

## 三、日常使用：三种方式

### 方式 A · 自然语言直接对话（最常用）
```
"分析一下宁德时代在动力电池环节的竞争位次"
"对比一下 A 股三家 CXO 龙头的盈利质量"
"复盘一下昨天的市场，重点看资金面"
"这条政策对半导体设备板块意味着什么"
```
智能体会自动完成：受理 → 注入偏好 → 路由 → 取数 → 校验 → 成稿。

### 方式 B · 填写任务卡（批量化、可追溯）
从 `templates/` 复制一张任务卡，填好后提交。适合需要留痕、需要复现的正式研究任务。

### 方式 C · 设定时任务（自动化）
把重复性任务固化为定时执行，例如"每交易日收盘后自动生成市场复盘"。适合每日复盘、关注池异动跟踪等高频场景。

## 四、修正机制：三条通道

客户对智能体的修正，按**生效范围**和**持久性**分为三条通道。混淆这三条是导致"越用越乱"的主因，务必区分。

| 通道 | 怎么说 | 生效范围 | 是否持久 | 用途 |
|---|---|---|---|---|
| **① 即时指令** | "这次结论写保守一点" | 仅本次任务 | 否 | 临时调整口径 |
| **② 偏好文件** | 直接修改 `profile.yaml` | 之后所有任务 | 是 | 明确的长期偏好变更 |
| **③ 反馈累积** | "你最近几次都漏了现金流分析" | 建议写入偏好 | 是（经确认） | 隐性偏好显性化 |

### 通道 ① 使用建议
临时指令**不会**污染偏好文件。如果某条临时指令你连用了三次以上，智能体会主动提示："这条要求已重复出现，是否写入偏好文件？"

### 通道 ② 使用建议
每次修改偏好后：
1. 递增 `meta.profile_version`；
2. 更新 `meta.last_updated`；
3. 在 `corrections` 段追加一条记录（日期、触发原因、具体变更）。

### 通道 ③ 使用建议
智能体在检测到同类反馈连续出现 3 次时，会给出**具体的字段级修改建议**，例如：
```
检测到：您连续三次追加询问"经营现金流质量"
建议：data_weights.fundamental 由 0.35 调整为 0.40，
      valuation 由 0.25 调整为 0.20；
      overrides.focus_metrics 追加 "经营现金流/净利润"
是否应用？
```
客户确认后才写入，不擅自修改。

## 五、偏好演进示例

一个客户从开始使用到偏好定型，典型的演进路径：

| 阶段 | 触发 | 变更 | 效果 |
|---|---|---|---|
| v1.0 | 初始配置 | value / medium / balanced / neutral / standard | 可运行 |
| v1.1 | 用了一周，觉得结论太温吞 | `conclusion_bias: neutral → conservative` | 结论更审慎 |
| v1.2 | 连问三次现金流 | `data_weights.fundamental 0.35→0.40` | 财务分析更重 |
| v1.3 | 开始做港股 | `market_scope: [A] → [A, HK]` | 覆盖港股 |
| v2.0 | 策略转型为成长 | `primary_style: value → growth`；估值方法切 PEG | 整套口径切换 |

**注意**：v1.0→v2.0 这类主风格切换，会连带改变估值方法、时间视角、核心关注指标。建议切换后**跑一个基准任务**（如一只熟悉的老股票），核对新口径是否符合预期，再投入正式使用。

## 六、版本管理与 Fork

```
推荐做法：
  profile.yaml 纳入自己的版本管理（Git / 云盘历史版本）
  主风格切换等重大变更，另存为 profile-<风格>-<日期>.yaml
  不要把 profile.yaml 与主干逻辑文件混在一起改
```

**Fork 规则**：
- 客户可自由 Fork 自己的 `profile.yaml`，形成多套人格（如"价值视角"与"短线视角"并存）；
- 客户**不应** Fork 主干逻辑文件（01/02/04/05）——若确有需要，请联系模式维护者走版本升级。

## 七、边界与合规

### 能力边界
| 能做什么 | 不能做什么 |
|---|---|
| 生成深度研究报告（深挖） | 替代持牌投顾出具投资建议 |
| 提供权威结构化数据（数据源） | 保证数据零延迟、零误差 |
| 交叉校验数字、标注冲突 | 消除所有分歧口径 |
| 按偏好裁剪输出 | 预测未来价格 |

### 合规底线
1. **不涉政治敏感话题**、暴力非法话题、基于谣言的话题；
2. 所有产出为 **AI 辅助生成**，仅供参考，重大投资决策前请人工复核；
3. 深挖报告**原文完整呈现**，不作摘要改写；
4. 深挖账号凭证（Token/browserCode）**不在任何对话中回显**；
5. 数据来自第三方源，可能存在延迟或误差，使用时须核对截取时点。

- 模式维护与二次开发：联系模式维护者

## 八、客户常见问题

**Q：为什么报告要等 3~10 分钟？**
A：深挖报告由平台异步生成，需要真实的分析时间。等待期间数据层内容会先就绪，不会空等。

**Q：为什么数字要跟深挖报告对一遍？**
A：深挖提供的是分析逻辑与结论，AI 生成内容中的具体数字需要独立核验。校验表就是为此存在，它占数据源 50% 权重的重要部分。

**Q：我改了偏好，为什么感觉报告没变化？**
A：检查三项——`profile.yaml` 是否保存、`meta.profile_version` 是否递增、本次任务是否有临时指令覆盖了长期设置。

**Q：能不能让它一次做完所有事？**
A：不能，这是刻意设计。单项任务才能保证可交付、可校验、可追溯。多任务会拆成多张任务卡并行执行。

**Q：深挖报告太长，能要个摘要版吗？**
A：可以要一句结论摘要（第 1 段），但**深挖分析主体不摘要**——它本身就是这份产出的核心价值所在。
