## 一、安装与启用

```
1. 复制整个 shenwa-hybrid-blueprint 目录到自己的工作区
2. 复制 03-偏好配置模板.yaml → profile.yaml
3. 打开 profile.yaml，填写「最小可运行配置」的 5 个必填字段
4. 保存，开始使用
```

**需要具备的能力**：一个可用的深挖（Shenwa）账号；一个可用的泛金融数据 skill 环境。
**不需要具备的能力**：编程。所有个性化都通过修改 YAML 文本完成。

### 接入方式（v1.1 明确，长期生效）

| # | 规则 | 说明 |
|---|---|---|
| 1 | **只走 API** | 深挖全部能力经 API 调用；任何情况下**不得使用浏览器抓取或访问** |
| 2 | **不需要邀请码** | 登录**只需注册手机号（userID）**，不需邀请码、不需密码；**不会向你索要邀请码** |
| 3 | **自动切备用站** | 主站 `https://www.shenwa.top` 不可达时，**自动切换 `http://8.130.17.247:8088`**，无需人工确认 |
| 4 | **异常不误报** | 连续调用异常时在主备站间重试退避；仍失败只报「无法获取状态」，**不会谎报"报告失败"** |

## 二、首次个性化：只需要决定 5 件事

| # | 字段 | 你要回答的问题 | 选项 |
|---|---|---|---|
| 1 | `identity.primary_style` | 你主要靠什么赚钱？ | 价值 / 成长 / 趋势 / 短线 / 量化 / 主题 |
| 2 | `identity.horizon` | 你看多长？ | 长（3-5 年）/ 中（1-3 年）/ 短（周-季） |
| 3 | `identity.risk_tolerance` | 你能承受多大回撤？ | 保守 / 中性 / 进取 |
| 4 | `identity.conclusion_bias` | 你希望结论怎么说？ | 偏审慎 / 中性 / 偏积极 |
| 5 | `output.depth` | 你要多细？ | 摘要式 / 标准 / 尽调级 |

填完这 5 项，模式即可运行。其余字段（数据权重、关注池、校验阈值）可在使用中逐步调优。

## 三、日常使用：三种方式

### 方式 A · 自然语言直接对话（最常用）
```
"分析一下宁德时代在动力电池环节的竞争位次"
"对比一下 A 股三家 CXO 龙头的盈利质量"
"复盘一下昨天的市场，重点看资金面"
"这条政策对半导体设备板块意味着什么"
```
智能体会自动完成：受理 → 注入偏好 → 路由 → 取数 → 校验 → 成稿。

#### 补充：怎么问「全市场扫描」（v1.3.0 新增）

有两类问法，走**两条完全不同的路**——先把"要名单"还是"要解读"说清：

| 你要什么 | 怎么问 | 走哪条路 | 代价 |
|---|---|---|---|
| **名单**（哪些板块/行业符合条件） | 「**今天哪些行业与主题指数出现了右侧确认**」「**哪些板块今天触发了否决**」「**排一下升级名单**」 | 接口直取（**不发报告**） | **0 点、秒级** |
| **解读**（某个板块为什么、接下来怎么走） | 「**PCB 板块现在处于右侧哪个阶段，成因是什么**」 | 发深挖报告 | 5 点/标的，1~5 分钟 |

**触发词**（命中即走直取通道）：全市场 / 所有行业 / 所有概念 / 哪些板块 / 哪个行业 / 扫一遍 / 筛一遍 / 排名 / 分布 / 有没有 / 集中在哪。

你拿到的是**四张表 + 计数**：

- **升级名单**（阶段上行）｜ **破坏名单**（阶段下行）｜ **临界名单**（资格接近达标）｜ **否决名单**（触发否决标志）
- 另附**阶段分布**（S0~S5）与**迁移分布**（Hold / Upgrade / Breakdown）

⚠️ **四点要知道**：

1. **覆盖范围是深挖右侧确认框架的官方精选池**（实测 62 个行业与主题指数）。表头会写明**本次实际返回**的覆盖数量与口径来源，**不会写死数字**，也**不是"全市场所有概念"**。另外，四类名单之间存在**重叠**，**不会相加**当作覆盖总数。
2. **这条通道需要账号有 ADM 或 VIP2 权限。** 若你的账号没有，智能体会**如实告知**（并给出升级联系方式），**不会**偷偷改成"逐个板块发报告"来充数——那会变成 `5 点 × N`，而你以为在做扫描。
3. **接口字段也要过质量门**（不是"接口给的就直接采信"）：出表前会先按目标日期切截面、再核对覆盖数量、重复记录、未知状态；**否决字段缺失时会被单列出来**，**不会**被当成"没有否决"。若返回为空或接口明确报错，会如实告知，**不会**把空结果说成"今天没有异常"。
4. **它只给名单，不给结论。** 想让它对名单里某几个标的做解读，直接说：「**先出名单，再挑前 3 个给我写报告**」——它会先给名单（0 点），再由你指定 top-N 发报告（5 点/个）。这就是「两段式」。
5. **它会把「说错了的」和「只是没核实过的」分开处理（v1.5.0）**：深挖原文**一字不删地完整归档**（连编号、生成时间、来源一起留），但**正文只放它认可的部分**——原文里已经确认说错的地方（比如估值用了错的市盈率），**不会再拿来支撑结论**；如果确实要展示，会明确标成「错误对照」。另外，像「站上均线比例 88.68%」这种**只从某份报告转述、还没独立核实**的数字，它会写明「尚未独立核实」，**不会**当成已确认事实来下判断。资料没取全时，它会**收缩交付范围**并告诉你缺了什么、有什么影响，而不是硬凑一个结论。

#### 补充：同一套事实，为什么有时只回一句、有时是完整报告（v1.9.0）

**偏好改变的是"怎么说"，不是"事实是什么"。** 风格、风险容忍度、结论语气只影响**顺序、措辞、强调与版式**；它们**不改变**客观判断、关键数字与证据状态——**不会**因为选了"进取"就把上行情景说得更重或更容易发生。

**交付形态看任务、不看篇幅**：同一个问题可以交付成**短答**（一句结论 + 依据 + 限制）、**比较表**（并列对照 + 口径说明）、**简析**（数据 + 一句判断）或**完整报告**（六段）。形态可以简化**结构**，但**关键依据与限制条件不会因此被删掉**——**简单任务简洁交付，复杂任务保留必要证据**。

- 只问一个事实 → **短答**，不附全文，但会告诉你"依据是什么、哪里还没核实"。
- 两个以上对象对照 → **比较表**，标明口径与截面。
- 数据已够解释 → **简析**，不强制再发报告。
- 需要完整推演 → **完整报告**（六段）。**任何形态下，深挖原文都完整归档**；正文没附全文时，会给归档入口。

> ⚠️ **只要求"查一下"或"整理我给你的资料"时，不会自动扩展成一份新研究**（v1.9.0）。

### 方式 B · 填写任务卡（批量化、可追溯）
从 `templates/` 复制一张任务卡，填好后提交。适合需要留痕、需要复现的正式研究任务。

### 方式 C · 设定时任务（自动化）
把重复性任务固化为定时执行，例如"每交易日收盘后自动生成市场复盘"。适合每日复盘、关注池异动跟踪等高频场景。

## 四、修正机制：三条通道

客户对智能体的修正，按**生效范围**和**持久性**分为三条通道。混淆这三条是导致"越用越乱"的主因，务必区分。

| 通道 | 怎么说 | 生效范围 | 是否持久 | 用途 |
|---|---|---|---|---|
| **① 即时指令** | "这次结论写保守一点" | 仅本次任务 | 否 | 临时调整口径 |
| **② 偏好文件** | 直接修改 `profile.yaml` | 之后所有任务 | 是 | 明确的长期偏好变更 |
| **③ 反馈累积** | "你最近几次都漏了现金流分析" | 建议写入偏好 | 是（经确认） | 隐性偏好显性化 |

### 通道 ① 使用建议
临时指令**不会**污染偏好文件。如果某条临时指令你连用了三次以上，智能体会主动提示："这条要求已重复出现，是否写入偏好文件？"

### 通道 ② 使用建议
每次修改偏好后：
1. 递增 `meta.profile_version`；
2. 更新 `meta.last_updated`；
3. 在 `corrections` 段追加一条记录（日期、触发原因、具体变更）。

### 通道 ③ 使用建议
智能体在检测到同类反馈连续出现 3 次时，会给出**具体的字段级修改建议**，例如：
```
检测到：您连续三次追加询问"经营现金流质量"
建议：data_weights.fundamental 由 0.35 调整为 0.40，
      valuation 由 0.25 调整为 0.20；
      overrides.focus_metrics 追加 "经营现金流/净利润"
是否应用？
```
客户确认后才写入，不擅自修改。

## 五、偏好演进示例

一个客户从开始使用到偏好定型，典型的演进路径：

| 阶段 | 触发 | 变更 | 效果 |
|---|---|---|---|
| v1.0 | 初始配置 | value / medium / balanced / neutral / standard | 可运行 |
| v1.1 | 用了一周，觉得结论太温吞 | `conclusion_bias: neutral → conservative` | 结论更审慎 |

**注意**：v1.0→v2.0 这类主风格切换，会连带改变估值方法、时间视角、核心关注指标。建议切换后**跑一个基准任务**（如一只熟悉的老股票），核对新口径是否符合预期，再投入正式使用。

## 七、边界与合规

### 能力边界
| 能做什么 | 不能做什么 |
|---|---|
| 生成深度研究报告（深挖） | 替代持牌投顾出具投资建议 |
| **全市场横截面扫描名单**（官方精选池，实测 60 余个行业与主题指数；**实际数量以本次返回为准**，0 点、秒级） | 覆盖 A 股**全部**概念板块（官方精选池是**有限集合**，**不是全部概念板块**） |
| 提供权威结构化数据（数据源） | 保证数据零延迟、零误差 |
| 交叉校验数字、标注冲突 | 消除所有分歧口径 |
| 按偏好裁剪输出 | 预测未来价格 |
| **报告原文本地归档**（完全可控） | **指定服务端的公开 / 私有**——发布接口**没有可见性参数** |
| 下载**深挖官方原文 PDF**（标注为「**原始报告**」） | 生成**专家包综合版 PDF**（当前环境**不支持**；会说明并改交 markdown / table / xlsx） |
| 发布后**调用删除接口**移除自己的报告 | 承诺**「服务端不保存」或「删除即彻底清除」**（无证据） |
| 因子暴露与分位（由数据源拼装） | **回测**（无净值 / 组合 / 交易成本链路，本包不做） |
| A 股研究（**已验证**） | 港股 / 美股研究（**仅有配置项，未经实测**） |

> **关于「能不能只存本地、不在服务端留档」**：做不到。深挖的发布接口（`wfStartPublish`）**没有可见性参数**，发布即入库；`public` / `private` 是服务端返回的**结果状态**，不是我们的选项。**本包能保证的是「本地归档」完全可控**；服务端的可见范围由服务端决定，本包**不承诺**。若确需移除，只能发布后调用删除接口，且**删除是否彻底无证据**。

### 合规底线
1. **不涉政治敏感话题**、暴力非法话题、基于谣言的话题；
2. 所有产出为 **AI 辅助生成**，仅供参考，重大投资决策前请人工复核；
3. 深挖报告**原文完整呈现**，不作摘要改写；
4. 深挖账号凭证（Token/browserCode）**不在任何对话中回显**；
5. 数据来自第三方源，可能存在延迟或误差，使用时须核对截取时点。

## 八、客户常见问题

**Q：为什么报告要等 3~10 分钟？**
A：深挖报告由平台异步生成，需要真实的分析时间。等待期间数据层内容会先就绪，不会空等。

**Q：为什么数字要跟深挖报告对一遍？**
A：深挖提供的是分析逻辑与结论，AI 生成内容中的具体数字需要独立核验。校验表就是为此存在，它占数据源 50% 权重的重要部分。

**Q：我改了偏好，为什么感觉报告没变化？**
A：检查三项——`profile.yaml` 是否保存、`meta.profile_version` 是否递增、本次任务是否有临时指令覆盖了长期设置。

**Q：能不能让它一次做完所有事？**
A：不能，这是刻意设计。单项任务才能保证可交付、可校验、可追溯。多任务会拆成多张任务卡并行执行。

**Q：深挖报告太长，能要个摘要版吗？**
A：可以要一句结论摘要（第 1 段），但**深挖分析主体不摘要**——它本身就是这份产出的核心价值所在。

**Q：我说"帮我扫一遍全市场的右侧确认"，为什么没花点数、还秒回？**
A：因为它的**指标族是「右侧状态」**，走的是**接口直取**而不是发报告——一次调用就覆盖官方精选池全量（最新实测 62 个行业与主题指数，**按本次实际返回标注**），**0 点、秒级**，产出四张表。这是**刻意设计**：用报告逐个板块扫，要 `5 点 × N` 且要等 N 次生成，成本随标的数线性膨胀。反过来，如果你要的是"**某个板块为什么涨**"，那属于**单标的纵深**，需要深挖真的写一份报告，会花 5 点、等 1~5 分钟——**两条路的区别不在难易，而在"要名单"还是"要解读"**。

**Q：全市场扫描怎么只覆盖 62 个？我想看某个概念板块。**
A：62 个是深挖右侧确认框架的**官方精选池**（行业与主题指数），它是这条路线的**固定覆盖范围**，不是"A 股全部概念"。想看你关心的具体板块，直接点名问它——那属于**单板块纵深**，会单独出一份板块级报告。

**Q：为什么会说"提交状态未知"？**
A：发布（`report_publish`）这类**有副作用**的调用，若请求已经发出但响应超时 / 异常，**客户端不会自动再发一次**（否则可能重复发布同一份报告）。它会先记一条**本地最小任务记录**，再用**只读**接口核对；如果拿不到 `aid`、无法与本次提交唯一对应，就如实返回「**提交状态未知**」而不是猜。这是**刻意设计**：宁可让你人工确认一次，也不产生无法回收的重复提交。⚠️ 本地记录**不是**服务端幂等保障 —— 客户端**不声称**已实现幂等。

**Q：报了几次"网络异常"，会不会重复发布？**
A：不会。只读接口（查状态、读列表）允许**有界**重试与换站；**发布 / 收藏 / 删除这类有副作用的接口一旦发出就不重发、也不换站重发**。另外「身份失效」与「权限不足」也已分开：前者**有限重登**，后者**直接告诉你权限不足，不会反复登录**。

**Q：我把风格改成"进取"，是不是结论就会更乐观、上涨概率就更高？**
A：**不会**。风格、风险容忍度与结论语气只改变**怎么说**——先讲方向还是先讲反面证据、风险段写多细、措辞多重。它们**不改变**客观判断、关键数字与证据状态，**也不会**提高或降低任何情景的概率或权重。这是刻意的：**同一套事实，不能因为表达偏好就变样**。若你要看不同假设下的推演，可以说"按 XX 假设再算一遍"，系统会**明确标为「假设变化」**（并保留基准值），而不是把它写成事实。

**Q：为什么同一个问题，有时只回一句、有时给一整份报告？**
A：看**任务深度与问题类型**，不看篇幅。一个事实 → **短答**（一句结论 + 依据 + 限制）；两个以上对象 → **比较表**；数据已够解释 → **简析**；需要完整推演 → **完整报告**（六段）。**形态可以简化结构，但不会删掉关键依据与限制**；深挖原文在任何形态下**都完整归档**，正文没附全文时会给你归档入口。

**Q：我要一份 PDF，能给我"综合版"的吗？**
A：要分清楚两种 PDF：① **深挖官方原文 PDF** —— 这是深挖平台自己排版的，我们会标为「**原始报告**」，可以给你；② **专家包综合版 PDF**（把深挖主体 + 数据 + 校验表合成一份）—— 当前环境**不支持生成**，我们会**如实说明**，并交付 **markdown / table / xlsx**。**不会**拿官方原文 PDF 冒充综合报告。

**Q：我只是让你"查一下这个数"，为什么给我写了一份研究报告？**
