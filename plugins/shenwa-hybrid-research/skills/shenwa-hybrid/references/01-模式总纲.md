# 01 · 模式总纲

## 一、设计目标

把「AI 深度研究报告能力（深挖）」与「结构化金融数据能力（泛金融数据 Skill）」组合成一个**职责清晰、可校验、可个性化、可复制**的投研智能体模式。

三个必须解决的问题：

1. **深度与可信度的矛盾**——深度结论往往由生成式模型给出，数字不可靠；而数据源有准确数字，却给不出结论。本模式让两者互相制衡。
2. **个性化与可维护性的矛盾**——越个性化的助手越难维护和分发。本模式把个性化全部外置成配置。
3. **能力边界模糊**——不同任务该找谁，容易扯皮或重复劳动。本模式用路由决策树显式规定。

## 二、四层架构

```
┌─────────────────────────────────────────────────────────────┐
│  L1 · 偏好层  Preferences                                    │
│  客户唯一可改区域：表达偏好（语言/长度/图表/结构/关注重点）    │
│                    + 任务约束（期限/比较目标/风险限制/方法）  │
│  文件：03-偏好配置模板.yaml                                   │
└───────────────────────────┬─────────────────────────────────┘
                            │ 注入偏好参数
┌───────────────────────────▼─────────────────────────────────┐
│  L2 · 路由层  Router            【固定，不可改】              │
│  任务受理 → 类型判定 → 分工定比 → 能力指派 → 交付形态确定     │
└───────────────────────────┬─────────────────────────────────┘
                            │ 派发子任务
┌───────────────────────────▼─────────────────────────────────┐
│  L3 · 能力层  Capabilities      【固定，不可改】              │
│  ┌──────────────────────┐    ┌──────────────────────────┐   │
│  │ 深挖能力域            │    │ 数据能力域                │   │
│  │ Shenwa API           │    │ 泛金融数据 Skill          │   │
│  │ 分析主体 / 深度结论   │    │ 事实底座 / 校验层         │   │
│  └──────────────────────┘    └──────────────────────────┘   │
└───────────────────────────┬─────────────────────────────────┘
                            │ 合并 + 校验
┌───────────────────────────▼─────────────────────────────────┐
│  L4 · 输出层  Output                                          │
│  按偏好裁剪：结构 / 深度 / 语言 / 格式 / 是否附可视化         │
└─────────────────────────────────────────────────────────────┘
```

**分层原则**
- L1 可改，L2/L3 冻结，L4 由 L1 驱动变化。客户改偏好只会改变"输出长什么样"，不会破坏"能力怎么调度"。
- **偏好二分（v1.9.0）**：L1 的偏好分**表达偏好**（语言 / 长度 / 图表 / 结构 / 关注重点）与**任务约束**（研究期限 / 比较目标 / 风险限制 / 明确指定的方法）。**两类都只影响"怎么说"与"研究什么范围"，一律不得改写事实**——风格、风险容忍度、结论语气**不改变**客观判断、关键数字与证据状态。
- 任何跨层修改（例如新增数据源）都属于模式维护者职责，需走版本升级流程。

## 三、50/50 分工的落地定义

### 分界原则：深挖出主体，数据源做校验

| 维度 | 深挖（Shenwa） | 泛金融数据 Skill |
|---|---|---|
| **角色** | 分析主体供给方 | 事实底座 + 校验方 |
| **内容性质** | 定性、逻辑、深度结论 | 定量、时点、可核验事实 |
| **典型产出** | 行业驱动拆解、竞争格局判断、公司逻辑链、事件影响推演、政策解读、风险清单 | 行情与估值快照、财务三表关键项、资金流向、股东结构、公告舆情、同业对标、选股筛选 |
| **时效性** | 结构性、中长期有效 | 强时效，标注截取时点 |
| **配比（内容权重）** | **约 50%** | **约 50%**（数据表 + 校验表计入） |

> 关键说明：校验表是数据源的产出，**必须计入那 50%**。否则"数据源只做核对"会被误读为数据源权重很低，破坏 50/50。

### 配比浮动规则

| 任务类型 | 深挖占比 | 数据源占比 | 说明 |
|---|---|---|---|
| 公司深度研究 | 50% | 50% | 基准场景，严格执行 |
| 行业分析 / 同业对比 | 50% | 50% | 基准场景，严格执行 |
| 事件复盘 | 55%~60% | 40%~45% | 事件解读对深度依赖更高 |
| 政策解读 | 55%~60% | 40%~45% | 同上 |
| 每日复盘 / 市场快报 | 30%~40% | 60%~70% | 数据密集，深挖仅提供观点定调 |
| 标的筛选 / 选股 | 20%~30% | 70%~80% | 筛选本身是数据任务 |
| 纯数据核查 | 0%~10% | 90%~100% | 无需深挖介入 |

**说明（v1.9.0 修订）**：上表是**建议区间**，不是硬性开关。若某任务的实际比重与基准不同，**只需在任务卡的「分工声明」栏写明理由**；
**不做自动回退**——旧版"未写明则自动回退到 50/50"已作废。比重的调整**只影响分工呈现，不改变事实与证据状态**。

## 四、单项任务闭环（七步）

```
① 任务受理  → ② 偏好注入 → ③ 路由判定 → ④ 并行取数
                                              ↓
      ⑦ 归档修正 ← ⑥ 成稿交付 ← ⑤ 交叉校验
```

| 步骤 | 动作 | 产出 | 责任人 |
|---|---|---|---|
| ① 任务受理 | 明确标的、时间范围、交付物、交付格式 | 任务卡（草稿） | 客户 + 智能体 |
| ② 偏好注入 | 读取偏好文件，确定结论口径与输出形态 | 生效参数集 | 智能体 |
| ③ 路由判定 | 判定任务类型，确定分工比例与能力指派 | 任务卡（分工声明） | 智能体 |
| ④ 并行取数 | 深挖异步发布报告（3~10 分钟）；同步并行取数据源硬数据 | 深挖报告 + 数据包 | 双能力域并行 |
| ⑤ 交叉校验 | 深挖正文中的可验证数字逐项核对，补齐缺口，标注冲突 | 校验表 | 数据能力域 |
| ⑥ 成稿交付 | 按**交付形态**组装（完整报告用六段；短答/比较表/简析按需），按偏好档位裁剪 | 最终交付物 | 智能体 |
| ⑦ 归档修正 | 记录本次偏差与客户反馈，回写偏好演进建议 | 任务归档 + 修正日志 | 智能体 |

## 五、模式约束（红线）

1. **数字分层采信**（最高优先级）：深挖数字的可靠性是**分区的**，不可一刀切采信，也不可一刀切禁用。

   | 深挖输出的数字类型 | 采信规则 |
   |---|---|
   | **财报类数据**（三大报表科目、财报衍生指标、同比环比、财务比率） | ⚠️ **第一来源是数据源**：一律优先从数据源取数；深挖正文中的同类数字**仅作对照物**，不得作为取数来源 |
   | **推算类比率**（比率、占比、增速、周转、覆盖倍数等） | **不得引用**，一律以数据源计算值为准 |
   | **估值类数字**（目标价、内在价值、DCF 值、估值倍数） | **不得引用**；深挖只可提供估值方法与假设框架，数值由数据源代入 |
   | **阈值 / 价格类**（买卖点、止损位、价格区间） | **不得引用**，由数据源的技术面数据推导 |
   | **事件类信息**（并购、订单、合作、监管动作） | 须由数据源独立确认后方可引用 |

   **深挖的引用价值在于其分析框架、判断逻辑与推演路径。**
   > 依据一：2026-09-25 对照实验实测 45 项可核验数字，整体一致率仅 33%，并出现 3 处量级级错误（股价 84.34 元被写成 220 元、目标价区间 206–305 元）。**财报科目是最容易被下游直接引用、也最容易出量级错误的一类，故其取数入口在 v1.1 起统一收归数据源。**
   > 依据二：同期实验发现，主要引用已披露财报科目的那组一致率达 63%（16 项中 10 项完全吻合）——**证明可靠性差异来自数字类型，而非模板优劣**。
   > 依据三（2026-09-26 端到端实跑）：某个股报告中，**3 个估值链输入锚点（当前 PE / PB / 股息率）全部失真**，深挖用"偏低的盈利基数 × 偏高的 PE 倍数"推出 DCF 与"折价 15%、安全边际充足"。→ **校验必须从估值链的输入端锚点开始；锚点失真只作废真正依赖该锚点的推演（不再「整链作废」），与该锚点无关的结论照常保留。**此外还发现 1 处**方向性误判**（称 ROIC 高于 WACC，实际 ROIC 低于 WACC），以及 1 处**报告内部自相矛盾**（风险情景 -30% 与悲观情景 -3.6% 并存）——内部一致性检查因此升格为每份报告的**固定检查项**。

2. **不虚构**：任何数字必须来自数据源，且标注来源与截取时点。无法获取就写"未获取"，不得估算替代。

3. **深挖原文完整归档**：引用深挖报告时不得摘要、改写、省略章节——深挖提供的是分析主体，主体不可被二次加工。**但"完整归档"不等于"采信其数字"，也不等于"正文照抄"**：**归档件**完整保留全文（含已确认错误的段落，附编号 / 时间 / 来源）；**正文（研究层）只呈现本轮认可的事实、推断、假设与局限**；数字以数据源为准（第 2、4 段）。三层并行，不冲突。

4. **拦截级不得进入正文**：偏差 > 50%、量级错误、或方向性误判的数字与结论，一律作废；整段依赖它的，**在正文中整段删除**。不得以"双值并列 + 标注存疑"的方式变相保留。⚠️ **该段落照常完整归档**，只是不得再支撑正文结论（见约束 15）。

5. **事件须独立确认**：事件类信息（并购、订单、合作、监管动作等）必须由数据源（公告、权威媒体）独立确认后方可进入交付物。数据源无法确认的，作为"未确认事件"单独列出，**不参与情景推演与概率计算**。

6. **任务组织**（v1.9.0 修订，替代原「单一任务」）：**一个总任务允许包含多个子任务**（如「扫描 + 比较 + 解释」），子任务**共享经过验证的数据**、去重取数、最后形成**统一结论**，避免重复取数与零散交付；但**不得**把与主题无关的事项打包进来。**「仅查询」或「仅整理用户提供的材料」类请求，不得自动扩展成新的深度研究。**

7. **口径一致**：同一任务内所有结论必须服从同一套偏好口径，不混用。

8. **可回滚**：偏好文件带版本号，每次变更留痕，可回退。

9. **合规底线**：不涉政治敏感、暴力非法、基于谣言的话题；产出为 AI 生成，重大决策前需人工复核。

10. **接入红线**（v1.1 新增）：**深挖只通过 API 访问**，任何情况下不得用浏览器抓取或访问；**登录只需注册手机号（userID），不需要邀请码**——不得向使用者索要邀请码，也不得因缺邀请码阻断流程；主站 `https://www.shenwa.top` 不可达时**自动切换备用站 `http://8.130.17.247:8088`**，无需人工确认；调用连续异常时在主备站间重试退避，仍失败只上报「无法获取状态」，**不得谎报"报告失败"**。

11. **模板择优复核**（v1.1 新增，v1.11.0 判据改版）：确定 tid 前仍须把 **tid=2001（智能深度推理）** 与初选模板正面比一次，**但「指标族数量」不构成改选 2001 的理由**——「任务跨多维度」「需求模糊」「初选需拼凑」**都不是判据**。**唯一合法的改选条件是：本层级专项模板覆盖不了用户已列出的问题（覆盖缺口）且层级为个股**（2001 是**个股级**模板）；其余情形保留初选（9 / 7 / 8 / 1001 / 3002）。判据与实现：`scripts/router.py` 的 `template_for()`（`coverage_gap` / `2001_eligible` / `switch_reason.by_family_count = False`）。**比较结论须写入任务卡「模板选型」栏。**

12. **数据口径前置**（v1.4.0 新增）：进入分析前先统一口径——最小字段约定（对象标识 / 指标定义 / 数值 / 单位 / 所属期间 / 公开或生效时间 / 取数时间 / 来源 / 处理方法），**缺失记「未知」，不补造**；区分 半年度 / 全年 / 单季 / TTM、MA 与 EMA、绝对与相对表现、指标水平与变化量、百分比与百分点；**先检查可比性，再计算差异**，相对偏差的分母统一取**基准值**，基准为 0 / 接近 0 / 符号变化 / 口径不可比时**明确处理、不机械套比例阈值**；冲突时**保留原值与来源、标冲突，不擅自选一个数充当真值**。执行入口：`skills/shenwa-hybrid/scripts/data_qc.py`。

13. **结构化接口不免检**（v1.4.0 新增）：`get_right_side` 等结构化返回**不因"是接口原始输出"而豁免检查**。按 **观测数据 / 计算指标 / 模型判定** 三层分开：本地质量检查只作用于前两层（**先按目标日期切截面**再统计；日期与代码唯一性、覆盖数量、重复记录、未知状态、否决字段三态），**模型判定只做一致性核对、不改判、不另造阶段标准**。⚠️ **否决字段缺失 ≠ 无否决**；**空结果 / 明确业务失败 ≠ 无异常**；**覆盖范围按实际返回展示，不写死数字**，多类名单重叠时**不得相加**。

14. **证据采信与结论确定程度**（v1.5.0 新增）：结论的确定程度**不得超过**其关键证据的状态——`verified`（已取得且口径明确**且已独立核实**）/ `unverified`（**未独立核实**）/ `conflict` / `pending` / `missing`；**「有来源」不等于「已独立核实」**。关键证据失效时，相关结论同步**撤回 / 改写 / 降低确定程度**。允许**明确标注的情景假设**，但不得用假设或估计冒充已披露事实；用户提出的观点先作为**待检验命题**。资料不足时交付能完成的部分并说明覆盖范围、缺项及影响，**不把有限检索样本写成市场或卖方整体共识**。实现：`skills/shenwa-hybrid/scripts/evidence.py`。

15. **归档层与正文层分离（v1.5.0 新增，用于消解规则冲突）**：「深挖原文必须**完整保留**」与「已确认错误必须**剔除**」**不构成冲突**——两者作用对象不同：**原始资料层**（归档件）完整保留全文（不摘要 / 不改写 / 不省略章节，**含已确认错误的段落**）；**研究层**（正文）只呈现本轮认可的内容，**已确认错误的原文不得继续支持正文结论**。字面冲突时一律按「**归档保留全文 + 正文禁用**」判定，而不是选一条规则执行。规则优先顺序：**接入合规 > 归档完整性 > 正文采信 > 证据状态标注 > 结论确定程度 > 交付范围**。

16. **估值方法与适用条件**（v1.6.0 新增）：估值前先做三件事——① **配对**：现金流与折现率必须同口径（**FCFF ↔ WACC** 折出**企业价值**；**FCFE ↔ 股权资本成本 Ke** 折出**股权价值**），错配即**拒绝计算**；② **桥接**：FCFF 折出的企业价值必须经「＋现金及非经营资产 －有息债务 －少数股东权益 －优先股 ±其他调整」才得**股权价值**，**缺必要调整项只给结果边界、不给每股价值**（**不得假定为零**）；③ **标注**：输入按 历史观测 / 已披露事实 / 未来假设 / 估计值 / 计算结果 分开标注，历史数据外推（如历史 CAGR）一律标为**预测假设**，声明期限、适用理由与敏感性，**不得**称为已验证的未来增长率。**永续增长率 ≥ 折现率时阻止永续公式**。实现：`skills/shenwa-hybrid/scripts/valuation.py`。

17. **方法准入与差异解释**（v1.6.0 新增）：估值方法按**研究对象与数据条件**选择，**不按用户风格强制**；**取消**「必须有 D7 才能输出估值」与「至少两种方法才算有效」两处一刀切——改为**逐方法检查必要输入与适用条件**，**某方法输入不足时只停止该方法**，齐备的方法**一个也算数**。多方法用于**解释差异**（输入 / 口径 / 时点 / 假设不同），**接近程度 ≠ 准确度**，**不得**因某方法结果偏低或偏离其他方法而剔除它，**不得**静默取平均。估值异常只影响**真正依赖该输入**的推演，**不因某个无关指标偏差而废弃整份报告**。已发布历史材料**不覆盖**，错误示例**另建修订版**并写明旧版问题。

18. **能力边界清单为准**（v1.7.0 新增）：能力的用途 / 输入 / 输出 / 对象层级 / 覆盖范围 / 必要依赖 / 权限 / 已验证程度 / 缺失时处理，**一律以 `references/09-能力清单.md`（由 `scripts/capability.py` 生成）为准**。状态四态：`verified_supported` / `conditional` / `unverified` / `unavailable`；**未验证 ≠ 不存在**，但**不得直接承诺支持**；`conditional` 须**先满足前提**（多为 VIP2 / ADM 权限）。**权限是硬门槛**：无权限时**如实告知**并说明升级路径，**不得**偷偷退回其它做法充当完成。**本地保存 ≠ 服务端公开 / 私有**：`wfStartPublish` 无可见性参数 → **不得承诺「私有发布」**；发布即入库 → **不得承诺「服务端不保存」**。**量化 / 回测 / 跨市场**按实际链路标注——**只有画像名称不等于完整具备**（回测为 `unavailable`，跨市场为 `unverified`）。

19. **路由六步顺序与能力分流**（v1.7.0 新增）：路由**必须**按 ① 研究问题 → ② 对象与范围 → ③ 指标 → ④ 时间范围 → ⑤ 所需深度 → ⑥ 可用能力 的**顺序**识别，**不可颠倒**。**选哪个能力只由「指标族」决定**；「排名 / 哪些 / 有没有 / 三个以上对象」等**语汇只影响批量方式**，**不得**据此决定分析类型。**`get_right_side`（S11）只用于「右侧状态」**（阶段 / 迁移 / 否决 / 资格），**乖离率**走 S8 或 D9、**估值**走 D1 与 D7、**财务比较**走 D2。**单对象可直取**（含简析），**多对象可深入分析**；**数据已足够解释时允许「数据 + 简析」，不强制另发报告**。模板选择与回退都要**重新检查对象层级 / 主题 / 指标 / 时间**；**不得无条件把复杂任务转给 2001**（2001 为**个股级**模板，板块 / 行业 / 产业链 / 宏观层级不得转），**不得在回退时悄悄改变研究问题**。**排名 / Top-N 必须说明排序标准**；关键歧义会实质改变结果时**简短澄清**，否则采用**透明、合理的默认值**并写明，**不得暗设用户投资风格**。实现：`skills/shenwa-hybrid/scripts/router.py`（`capability.py` 提供能力清单）。

20. **表达与事实分离**（v1.9.0 新增）：**风格 / 风险容忍度 / 结论语气只改变"怎么说"**（顺序、措辞、语气、强调、版式），**不得改变**事实、关键数字、证据状态、结论判定与方法适用条件。**删除**「因为用户进取就增加上行情景概率或权重」这类规则。用户明确要求的不同假设情景**可以推演**，但必须标为**[假设变化]**（保留基准值），**不得**写成事实变化。

21. **交付形态按任务不按篇幅**（v1.9.0 新增）：交付形态分 **短答 / 比较表 / 简析 / 完整报告** 四种，由**任务深度与问题类型**决定，**不按内容篇幅**强制、**不做无理由自动回退**。**关键问题的回答必须完整、重要结论必须有依据、证据不足必须可见**。**六段结构保留为「完整报告」的一种形式**，不强制用于所有任务；摘要式**正文可不附深挖全文**，但**归档件始终完整保留**并按需提供入口。**输出格式转换不得改变结论、数字与验证状态**；深挖官方原文 PDF 一律标为「**原始报告**」，**不得**冒充专家包综合报告；当前环境无法生成综合版 PDF 时**说明并交付支持的格式**（markdown / table / xlsx）。

22. **权重语义与复合任务**（v1.9.0 新增）：`data_weights` 是**阅读 / 关注权重**（先看哪一类、取数勾选哪些、版式详略），**不是**已校准的量化模型，**不产生**加权评分；若只是阅读 / 关注权重，必须**明确说明**，**不得**冒充已校准的量化模型。**复合任务**（一个总任务含多个子任务）应共享经过验证的数据、**按键去重**、同一键不同值时**并列原值并标冲突**，最终形成**统一结论**。

23. **多维需求一条不丢**（v1.11.0 新增）：用户一次提出的**多个问题**必须**逐个登记、逐个回答**，
**问题数量 ≠ 指标族数量**——同一指标族可含多个问题，一个问题也可跨多个指标族，**不得按指标族合并问题**；
路由命中多族时**全部保留**（`families`），不再只取优先级最高者。需求清单 / 取数 / 模板候选 / 校验 / 交付逐环按问题对齐。
实现：`skills/shenwa-hybrid/scripts/requirement.py`（`build_requirements()`）。

24. **执行方式按证据缺口选**（v1.11.0 新增）：**「出现分析二字」「命中两个以上指标族」都不是发报告的理由**。
已有接口能满足的事实查询 → **直接取数**；已有数据能算 → **直接计算并保留口径**；现有资料足够 → **用现有资料完成、不发新报告**；
**存在实质证据缺口且模板能力匹配** → 才进入**报告候选**；有缺口无模板 → **如实列缺**。一个任务**可组合**多种执行方式。
交付前对照问题清单做**覆盖检查**（是否每个问题都登记处理）与**完成检查**（是否已有足够证据并实际回答）；
**「缺资料」不算完整回答，不得用其他问题的结论代替**；存在未完成的必需问题时，**整体不得标记为全部完成**。
实现：`scripts/requirement.py`（`choose_execution()` / `deliver_gate()`）。

25. **报告发布一律经真实入口，不得绕过检查**（v1.12.0 新增，优先级仅次于红线 1）：每次报告发布都要有**明确的用途和任务条目对应**。发布计划由 `publish_plan.build()` 生成（条目编号**提交前生成**），实际提交**一律经 `publish_plan.publish()`** —— 它先跑五项检查（必要性 / 历史报告状态 / 计划覆盖 / 授权与预算 / 参数一致性），**只有通过才真的调 `report_publish`**，否则**发布调用次数恒为 0**。**不得在 SOP 里直接调 `report_publish`**。**报告份数由模板能力、具体问题、有效复用共同决定**：**不得默认「一家公司等于一份报告」**，**不得为凑齐计划而给「直取 / 计算 / 已有资料足够」的问题新增报告**，**也不得静默缩减**用户要求的对象数量。检查后**对象 / 模板 / 输入材料 / 提交参数有变化**时，必须**重新检查**。
实现：`skills/shenwa-hybrid/scripts/publish_plan.py`（`build()` / `gate()` / `publish()`）。

26. **预算三态与成本口径**（v1.12.0 新增）：预算分清**已结算消耗** / **尚未结算的预留占用** / **拟新增**（**已结算不再计入预留**）；**账户余额 ≠ 已授权额度**；**数量提醒不自动缩减研究范围**。**预计成本 = Σ(各条目模板成本)**（来源 = `templates` 接口 `cost`）；**成本未知 → `unknown`，不按 0 处理**。模板价格只用于**估算**，**只有获得扣点依据才标「实际消耗」**。并发时**「检查剩余额度 + 预留本次成本」必须原子完成**，防止分别通过后合计超额。授权内**不逐份询问**，超出时**只暂停受影响条目**。
实现：`publish_plan.BudgetLedger`（`reserve()` 在同一把锁内完成检查与预留）。

27. **提交状态、aid 绑定与结果未知的保护**（v1.12.0 新增）：条目编号**提交前生成**，**不按返回顺序分配报告**；aid 回来**绑定原条目**再关联对象与问题，**乱序也不串**。⚠️ **aid 只代表服务端受理，不代表报告完成、更不代表问题已回答**。提交超时 / 中断**沿用 `submit_unknown` 保护**，**不换站重发**；**结果未知保留占用**；**只有确认未消耗或取得结算依据后才调整占用**，**服务端生成失败也不等于未扣点**。恢复任务**先读已有状态**，已受理 / 结果未知**不得当新任务重复提交**。复用检查只记三态，**内容有效性判定属第 4 轮**（本轮记 `partial`）—— **v1.13.0 已实现，见规则 30 与 `scripts/reuse.py`**。

28. **背景要有据、可独立理解**（v1.13.0 新增）：背景**一律经 `publish_plan.assemble_background()` 组装**并**记录实际发送的文字**。**已核实数字带来源 / 时间 / 单位 / 口径**；**未核实材料标状态**；**用户观点写成待检验命题**；**独立判断时**不注入既有判断 / 预设结论；**解释 / 验证既有判断**时可提供并注明来源 / 时间 / 用途。**只选关键背景**，完整材料留本地。🔴 **不假设深挖能读本地路径 / 文件名 / 材料编号**。**超限（`text` > 500 字）不静默截断** —— 调整条目或执行方式，并**重新检查覆盖与预算**。
实现：`publish_plan.assemble_background()` / `check_text_length()`。

29. **来源关系：同源 / 复述不得充作独立证据**（v1.13.0 新增）：材料登记追踪 **对象·问题编号 / 材料编号 / 来源与可核对位置 / 三类时间（未知显式标记）/ 含义·单位·口径 / 核实状态 / 原始事实·计算·外部判断·用户观点 / 引用·转述·同源关系**。**来源关系是补充信息，不替代五态证据校验**。**深挖复述已传入背景数字 ≠ 新增独立证据**；**不同接口同底层材料 ≠ 独立验证**；关系未知**标 `unknown`**（**不默认独立、不武断同源**）；**按具体证据判定**；**不得仅因结果一致就写「两路独立验证一致」**。
实现：`scripts/evidence.py`（`SourceGraph` / `independence()` / `echo_check()` / `can_claim_two_way_independent()`）。

30. **历史报告复用按内容判定**（v1.13.0 新增）：**列表 / 标题 / 模板 / 对象 / 日期只用于找候选**；**复用须看内容及其依据**（对象与层级 / 是否回答当前问题 / 截止时间 / 假设·情景·输入材料 / 完成与可读 / 证据校验状态），**逐题**四档：**完整复用 / 部分复用 / 仅历史参考 / 不适用或待核实**。**不机械比对文字**；**同日同对象同模板但问题不同不得直接复用**；**跨日稳定信息可用、时效数据须重查**，旧结论依赖已变数据**必须重新分析**；用户要求**新时点 / 新情景 / 重做不得用旧报告替换**。复用结果**关联问题编号**，完整复用内容**进入该问题的证据与回答**；调整计划后**重算预计新增消耗并核对授权**；**不得清除已提交 / 结果未知条目的状态与占用**；**不得为降份数降深度或减对象覆盖**。
实现：`scripts/reuse.py`（`judge_reuse()` / `apply_reuse()` / `recompute_plan_cost()`）。

## 六、为什么这样设计能"被客户改而不被改坏"

| 客户可能的改动 | 影响范围 | 是否安全 |
|---|---|---|
| 改投资风格、时间视角、风险容忍 | L1 → L4 输出形态变化 | 安全 |
| 改输出深度、语言、格式 | L1 → L4 裁剪规则 | 安全 |
| 改关注池、市场范围 | L1 → L3 取数范围 | 安全 |
| 改校验容忍阈值 | L1 → L5 校验判定 | 安全 |
| 改分工比例 | 写明理由即可 | 受控 |
| 改结论语气 / 风险容忍 | L1 → L4 呈现顺序与措辞 | 安全（**不改事实与数字**） |
| 改交付形态（短答/比较表/简析/完整报告） | L1 → L4 结构 | 安全（**关键依据不删**） |
| 一次提多个问题 / 拆出多个维度 | L2 → L3 逐项路由（**多维需求一条不丢**） | 安全（**不按指标族合并问题**） |
| 改能力清单 / 替换数据源 | 属模式维护者职责 | 走版本升级 |
