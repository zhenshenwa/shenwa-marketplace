> 用途：为路由层提供**可量化**的模板选择依据，替代此前的经验判断。

## 二、五条量化发现

### 发现 1 · 体量区分度比预期低得多

15 个已测模板的分布：

```
1,800 ~ 2,500 字（轻）  ██████████  10 个
2,500 ~ 3,500 字（中）  ████         4 个
> 4,000 字    （重）  █             1 个  ← 仅 tid=3002
```

**结论**：深挖模板体量高度集中在 1,800~3,300 字，**只有 tid=3002 一个异常**（4,761 字，是次长者的 1.44 倍）。

**对 C5 的影响**：原设计的「模板体量预警」机制区分度不足，实际只需针对一个模板。**不必维护四级体量体系，改为一份"重体量模板黑名单"即可。**

### 发现 2 · 标的层级可被客观判定

`stocks` 字段挂载的标的数量，直接反映模板的标的层级，无需人工标注：

| 挂载标的数 | 标的层级 | 模板 |
|---|---|---|
| **0（`stocks` 为 null）** | **市场 / 事件级（不挂具体标的）** | **12** |
| 1 | **个股级** | 0, 7, 8, 9, 2001, **1001** |
| 2 | 个股级（A+H）或行业代表 | 1, 4, 6, 10 |
| 5 | 题材级 | 2, 5 |
| 8 | 主题级 | 3001 |
| 10 | 板块级 | 3002 |
| 14~16 | 产业链级 | 3, 11 |

**这是本次测量最有价值的产出**：路由层不再需要靠人工维护"哪个模板是什么层级"，而是**发布后可自动校验**。

### 发现 3 · C4 与 C5 指向同一个模板

「标的层级错配」与「体量倒挂」两个问题，实测下来**都只由 tid=3002 触发**：

- 板块级（挂载 10 只）→ 个股任务用了它就错配；
- 重体量（4,761 字）→ 与 `light` 配比组合就倒挂。

两条修正可以合并为一条更简洁的规则：

> **个股层级的任务禁用 tid=3002（右侧区间监测助手）。**

### 发现 3·补 · tid=3002 的适用边界已收窄为「单板块纵深」（v1.3.0 新增）

单独成条，因为它决定了**"该不该发报告"**：

| 任务形态 | 该不该用 tid=3002 |
|---|---|
| **单板块纵深**（一个板块要读成因 / 推演 / 判断 / 确认与失效条件） | ✅ **正是它的用武之地** —— 是板块 / 主题级右侧结构监测的**唯一合适模板** |
| **右侧状态族横截面**（指标族 = 右侧状态 / 阶段 / 迁移 / 否决 / 资格，且深度为名单 / 分布） | ❌ **禁止**。改用 `get_right_side`（能力 S11）直取：**一次调用覆盖官方精选池全量（实测 62 个指数）、0 点、秒级**。用 3002 得发 N 次（`5 点 × N`），成本随标的数线性膨胀。⚠️ v1.7.0：**「全市场 / 所有行业 / 哪些板块 / 排名 / 分布」只影响批量方式**；**乖离率 / 估值 / 财务比较**各自进入适配能力，也**不得**据此判为「不可用 3002」 |

> **口径**：3002 的定位是「**把一个板块看透**」，不是「**把一批板块扫一遍**」。前者它无可替代，后者根本不成立——**用显微镜数星星，每一次都准确，但没有意义**。
> **细则**见 `02-能力分工与路由.md` 的 **Q0.9 / C19**。

### 发现 4 · 生成耗时的真实分布

原设计预估"3~10 分钟"。实测：

| 模板类型 | 实测耗时 |
|---|---|
| 轻体量（个股、事件、概念） | **3~5 分钟** |
| 中体量（关键词跟踪） | **8~13 分钟** |
| 重体量（右侧区间监测） | 5.5 分钟（但 tid=1001 超 13 分钟未完成） |

**修正**：告知客户时应改为「**一般 3~5 分钟，个别模板可能超过 10 分钟**」；轮询上限须从"最多 24 次 × 30 秒 = 12 分钟"**放宽到至少 40 次（20 分钟）**，否则会误判为超时失败。

### 发现 5 · tid=2001 是通用型「择优基准」（v1.1 新增）

`2001 智能深度推理` 的模板语义是**按需求自适配分析流水线**——它**不预设固定分析维度**，而是根据 `question` 自适应决定分析框架，因此天然适合**跨维度、边界模糊**的任务。

| 维度 | 2001 的表现 |
|---|---|
| 体量 | 2,297 字（轻），处于全量分布的中位区，不会造成配比倒挂 |
| 标的层级 | 挂载 1 只 → **个股级**，可用于全部个股任务 |
| 耗时 | 5.5 分钟，属轻/中体量的正常区间 |
| 实测战绩 | 量化因子场景下**零拦截级**（原用 tid=7 出现 2 处拦截级 + 1 处结论级错误） |
| 适配性 | 不预设维度 → **多问题任务无需拼凑多份报告**（⚠️ 这是**能力描述**，**不构成「族多就选 2001」的判据**） |

**规则（v1.1 起强制；v1.11.0 判据改版）**：**每次确定 tid 之前，必须把 2001 与初选模板正面比较一次**，并把比较结论写入任务卡「模板选型」栏。⚠️ **判据与指标族数量无关——唯一改选条件是「本层级专项模板覆盖不了用户已列出的问题」且层级为个股。**

```
Q6 模板择优复核
  ├─ 唯一改选条件（v1.11.0）：本层级专项模板**覆盖不了用户已列出的问题**（覆盖缺口）**且层级为个股**
  │    ⚠️ 以下均**不构成**改选理由：任务跨多个分析维度 / 需求偏模糊 / 初选需多份拼凑 / 指标族数量多
  ├─ 命中以下任一 → 保留初选
  │    ① 本层级有覆盖用户全部问题的专项模板：9=偏公司估值 / 7=偏财务风险排查 / 8=偏新闻影响
  │        / 1001=巴菲特视角（价值） / 3002=板块右侧监测 / 12=市场日报
  │    ② 初选的层级或体量约束是本任务必需（如板块级必须 3002/3001）
  └─ 输出：选定的 tid + **一句话理由**（写入任务卡）
```

## 三、两个补测模板的结果（首次失败原因复核）

| 模板 | 首次现象 | 原因 | 补测结果 |
|---|---|---|---|
| **tid=12 智能投研日报** | 发布直接返回 `success=false`，`msg`：「所有模板均以当前时间截面为分析框架，**对未来时间截面的分析不准确**，请您更换为当前时间相关的分析需求。」 | 深挖有**时间截面语义校验**：背景消息中的日期若与系统当前日期不一致（哪怕只差一天），会被语义层拦截。**任务卡的日期字段必须取自系统当前日期，不可写死。** | 从 `getLatestVersion` 取服务端当日日期（`2026年9月26日`）写入背景消息后，**发布成功**；2,119 字，`stocks=null`（不挂载标的），2.5 分钟完成。 |
| **tid=1001 巴菲特视角** | 发布成功，但轮询 26 轮（13 分钟）仍未完成，超出当时脚本上限 | 该模板耗时**有过大抖动**（服务端排队 / 冷启动），非模板固有耗时 | 放宽轮询至 40 轮后，**2.5 分钟即完成**；1,457 字，挂载 1 只（个股级）。 |

**净结论**：两个"未测"模板都不是数据问题，而是**流程参数问题**——一个是**日期必须动态取**，一个是**轮询上限必须放宽**。二者均已回写进 SOP 第 ④⑧⑤ 步。

## 四、路由决策的落地形式（替代原 Q5）

原 `02-能力分工与路由.md` 的 Q5「模板体量校验」替换为更直接的两条：

```
Q0.9 通道判别（v1.3.0 新增；**v1.7.0 判据改为「指标族 + 深度」**）
  ├─ 指标族 = 右侧状态（且深度 = 名单/分布）→ **不发模板**
  │     走 get_right_side 直取（S11）：0 点、秒级、一次覆盖官方精选池全量（实测 62 个指数）
  │     ⚠️ 「全市场/所有行业/哪些板块/排名/分布」只决定 `codes` 是否留空（批量方式）
  │     ⚠️ 乖离率 → S8/D9；估值 → D1/D7；财务比较 → D2（**各走适配能力，不发模板报告时用「数据 + 简析」或文比较**）
  └─ 其余（含单标的纵深）→ 继续下面 Q0 / Q5 / Q6

Q0 标的层级判别
  ├─ 个股层级 → 只在 {0, 1, 7, 8, 9, 10, 1001, 2001} 中选模板
  │              禁用 3002（板块级 + 重体量）
  ├─ 板块层级 → 3002 / 3001
  ├─ 行业层级 → 4 / 5 / 6
  ├─ 产业链   → 3 / 11
  └─ 市场/事件层级 → 2 / 12

Q6 模板择优复核（v1.1 新增，不可跳过）
  └─ 把 tid=2001 与 Q0/Q5 初选模板正面比较，写入任务卡「模板选型」栏
     （判定表见「发现 5」）

发布后自动校验（新增）
  ├─ 读取返回记录的 stocks 挂载数
  ├─ 若任务为「个股」而挂载数 > 2 → 层级错配，告警并要求重选模板
  ├─ 若任务为「板块/产业链」而挂载数 < 3 → 层级错配，同上
  └─ 特别注意：tid=12 的 stocks 为 null（市场/事件级），不得用于个股任务
```

**这条"发布后自动校验"是本次测量带来的净增量** —— 此前层级错配只能在人工阅读产出时才发现（首轮实验的 P3 组就是这样被发现的，且已浪费一次生成）。
